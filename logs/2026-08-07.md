## 気づき・メモ

- **前タスクの学びが 3 回目の再発をした。** MB-01 を「価格記録あり」の商品でしか測らず、
  **0 件用のデータ（にんじん）を自分でシードしていたのに使わなかった。** 結果レビューが
  Must（0 件時にスケルトン 256px → 空状態 86px で縮み、直下の「この商品を削除」ボタンが
  55px 上へジャンプ）を見つけた。前タスクで既に 2 回記録済みの
  「**確認項目の前提条件を満たすデータを選ばないと、自動化スクリプトは何も無いことを
  PASS と報告する**」と同型。**シードしたデータを全部使ったか、を確認手順に入れる必要がある。**
- **FAIL を見てから PASS 基準を変えるのは構造的に危険。** MB-01 は一次計測で「チャート下要素の
  Y が 115px 動いた」ため FAIL としたが、測定窓が広く既存シフトを取り込んでいた。基準を
  「チャート切替に起因するシフト」へ絞ったが、**これは正当化になり得る**ので独立した直接測定
  （「価格推移」セクション高が 284px で切替前後同一 → 下の要素は動き得ない）で裏を取った。
  実際の原因は `PriceRecordForm` の店舗一覧の非同期取得で、`layout-shift` の `sources` が
  「価格推移セクション**自身**が下へ動いた」＝原因はその上、と示していた。
- **環境の状態不整合が偽の FAIL を作るのは 2 回目。** バンドル計測で `next build` した後の
  `.next` を残したまま `next dev` を起動したら商品詳細ページが 404 になり、旧 UseCase を使う
  編集ページと API は 200 だったので**「新 UseCase の欠陥」と判断しかけた**。実際は本番ビルド
  成果物と dev の不整合で、ファイルを 1 度触って再コンパイルさせると解消（`git diff` 差分なし）。
  前タスクの「dev 起動中に PGlite を再シードして古い状態を掴んだ」と同型。
  → **`next build` の後に dev 確認をするなら `.next` を消してから起動する。**
  これは環境の恒久的な事実なので `docs/07-dev-rules.md` §環境の既知の事実 への追記を検討する。
- **テストの置き方が検出力を殺す（前タスクの `it.each` 範囲表記と同系統）。** M-1 の回帰ガードを
  既存テストファイル内に置いたら、先行テストの `render()` で dynamic import が解決済み
  （モジュールキャッシュ）になり**バグのある実装でも PASS した**。vitest はテストファイル単位で
  モジュールレジストリが分かれるので、独立ファイル `product-detail-client.lazy-chart.test.tsx`
  へ分離して真の Red を得た。
- **性能タスクは「測り方」を設計段階で実行検証すべき。** 設計書の測定方法は
  「`next build --webpack` がルートごとの First Load JS を印字する」前提だったが、
  **このバージョンの Next.js は Route 表にサイズ列を出さない**（実行して判明）。
  チャンクファイル直接計測へ差し替え、ベースラインを先に取ったことで B の Red/Green が成立した。
  取らずに進めていたら「改善したはず」で終わっていた。
- **RTL で検証できない要件を切り分けられた。** 計画者が「`PDC-13/14` は変更前でも PASS する」と
  正直に報告してくれたので、「B の真の Red はバンドル計測側にある」と明示し Step 4 を
  Step 3 と不可分の完了条件にした。**「Red が失敗しなかった」を欠陥ではなく仕様として
  記録する**形に整理できた。
- **等価性の参照値に「変更していない既存経路」を使うのが効いた。** MB-03 で
  `cheapest-store` API（旧 UseCase）の戻り値を参照値にして新 UseCase の画面出力と
  突き合わせた。期待値をハードコードするより強い。
- **レビューへの上限指示が効いた。** 前タスクの reviewer は 46 ツール呼び出し・13 時間で
  成果物ゼロのまま失われたが、今回は上限（40 回・20 分）と観点 5 点を明示して渡し、
  **27 呼び出しで成果物が出た**。しかも Must を 1 件見つけている。
- **既存の CLS を発見した（スコープ外）。** 商品詳細ページには `PriceRecordForm` の
  店舗一覧の非同期取得による 115px のレイアウトシフトが存在する。本タスクでは触っていない。

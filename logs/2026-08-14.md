## 気づき・メモ

### 差し戻し PR の原因記述が、次の再導入の選択肢を先に狭めていた

ADR-0019 の実行記録と `docs/07-dev-rules.md` は、原因を「Vercel `sin1` から Neon へ WebSocket
接続できない」と読める書き方をしていた。だが差し戻し前のコード
（`e3fe8f5^:packages/infrastructure/src/db/client.ts`）は
`neonConfig.webSocketConstructor = WebSocket`（`ws`）を**設定済み**で、初歩的な設定漏れではない。
同じ症状を説明できる候補が他にある。

| 候補                             | 根拠                                                                                                                                                            |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A: `ws` のバンドル事故           | `next.config.ts` の `serverExternalPackages` は `@electric-sql/pglite` のみ。`ws` は webpack ビルドに取り込まれ、`bufferutil` / `utf-8-validate` の動的 require が壊れやすい |
| B: `globalThis` の `Pool` 陳腐化 | `max: 1` の `Pool` を `globalThis` に載せていた。freeze / thaw で切れた接続を配る。`connectionTimeoutMillis` は新規接続の取得にしか効かず、約 15 秒の滞留と符合する |
| C: WebSocket 非到達              | 当初の結論。A・B を潰しても再現するなら確定                                                                                                                     |

障害対応の「原因が確定した」は、症状が消えたことと同義ではない。差し戻しで症状は消えるが、
それは切り分けの完了を意味しない。**記録には観測と推定を分けて書く。**

### 前回の障害はコードの欠陥ではなく検証経路の欠落

`docs/reviews/uow.md` の H-01 は「Preview で買い物リスト生成・完了・献立同期・店舗削除を
一巡させてから本番へ」を推奨 reject として挙げていた。これを飛ばして本番へ入れたのが原因。
自動試験は PGlite だけで、本番の接続方式・保存確定・巻き戻しを一切観測しない。
`pnpm test` が緑でも本番が落ちる領域があることを dev-rules に固定した。

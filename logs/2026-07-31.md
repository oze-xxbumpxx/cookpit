### 気づき・メモ

- **移行が不要になる設計を選べた。** `package.json` の `name` が `cookpit` なので
  `${name}-harness` = `cookpit-harness` で**現行の状態ディレクトリと完全一致**する。
  サフィックスを `-harness` にしたのは偶然ではなく、現行値との一致を設計目標に置いたから。
  実装計画で「導出結果が一致しなければ中断してユーザーへ報告」を独立ステップ（手順 3）に
  したうえで実測 → 一致を確認。**移行スクリプトを書いてから不要と気づくより安い。**
  将来この前提が壊れたら検出できるよう、回帰テストで `cookpit-harness` を固定した。
- **`STATE_NAMESPACE` の参照元が 2 ファイルしかないと先に確認したのが効いた。**
  `harness-paths.mjs` 自身とテストだけで、他 11 ファイルは `statePath` / `safeStatePath` /
  `resolveReadablePath` 経由で名前空間を知らない。**前セッションで挙げた
  「テストが namespace リテラルをアサートしているかも」という懸念は外れていた**
  （シンボルで import していた）。懸念は調べれば消える。
- **固有名詞の棚卸しを個別の変数名で grep して取りこぼした。** `COOKPIT_TZ` を列挙して
  探したため `COOKPIT_GAP_CAP_MIN` を見落とし、実装中に発見して設計書 R-3 を更新した。
  目的はプレフィックスの棚卸しなのに検索式が葉を指していた。
  **棚卸しは `grep -rn 'COOKPIT_'` のようにプレフィックス単位でやり、全ヒットを分類する。**
  分類の結果 `COOKPIT_METRICS_*`（11 箇所）は「利用者が設定しない内部受け渡し」として
  対象外に仕分けた。この仕分け自体は有益だった。
- **Prettier が Markdown を静かに壊した。これが今回いちばん危ない発見。**
  `--write` で `GAP_CAP_MIN` が `GAP*CAP_MIN` に、`'COOKPIT_'` が `'COOKPIT*'` になった
  （`_` を emphasis と解釈）。さらに表セルに書いた `HARNESS_TZ || COOKPIT_TZ` の `|` が
  列区切りと解釈され、区切り行に列が 4 つ増えた不正な表になった。
  **内容が変質しているのに品質ゲートは PASS する。** Prettier は Markdown として正しく
  整形しており、素のテキストでコード断片を書いた側の問題。
  → 識別子・シェル式は必ずバックティックで囲む。`--write` の後は生成物を目視する。
- **`git add` のパス列挙で 1 ファイル漏らした。** 新規 3 本を明示 add する必要があったので
  パスを列挙したが、実装計画の「変更対象ファイル」表に載っていた
  `docs/claude-code/harness-state.md` が抜けた。コミット直前の `git status` にも出ていたのに
  照合しなかった。Stop hook の未コミット検出で気づいた。
  **実装計画に変更対象ファイル表があるのだから、コミット前にそれと `git status` を突き合わせる。**
- **`harness-paths.mjs` の公開 API 14 件中 7 件が元から未テスト**と判明（試験計画の
  メソッド網羅チェックで発見）。`stateDir` / `statePath` / `safeStatePath` /
  `resolveReadablePath` / `hasSafePermissions` / `repoRoot` / `legacyState*`。
  本タスク起因ではなくスコープ外としたが、**Phase 2 で他プロジェクトへ配る前に埋めたい**
  （配布後は不具合の影響範囲が広がる）。backlog の申し送りへ起票した。
- リモート環境は `node_modules` 未インストールで、初回のゲートは lint / type-check / build /
  test が環境要因で FAIL した（harness だけ PASS = Node 標準のみで動く証拠）。
  `pnpm install --frozen-lockfile` 後に再実行して実測し直した。**環境要因の FAIL を
  変更起因と混同しないこと。**

  いずれも `accepted/` と `archive/` 配下で「歴史的ドキュメントは書き換えない」方針の対象。

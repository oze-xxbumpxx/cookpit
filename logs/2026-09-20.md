## 気づき・メモ

### 発見した実バグ: `Intl.DateTimeFormat` の `timeZone` 未指定（`c1d2d50`）

スクリーンショット撮影中、dev ツールバーが "1 Issue" を出していたのを追跡して発見。
`apps/web/src/app/products/_utils/product-format.ts` の `formatDate` / `formatDateTime` が
`timeZone` 未指定で、`observedAt`（`toISOString()` の UTC 瞬時値）を実行時 TZ で整形していた。
サーバ（Vercel は UTC）とブラウザ（JST）で 9 時間ずれ、SSR とハイドレーションで文字列が
不一致になりツリーが再生成されていた。

- 影響は `/products/[id]` だけでなく **`/products` の一覧カードにも及んでいた**
  （`product-card.tsx` が同じ関数を使用）
- 修正は `timeZone: 'Asia/Tokyo'`。`TZ` 環境変数での固定は Vercel の予約環境変数のため
  使えず、`packages/application/src/pantry/expiry.ts` と同じくコード上に明示する流儀に揃えた
- 同種の箇所が他に無いか全数確認: `formatExpiresAt` は文字列を直接分解、
  `formatShoppingDate` は構築と整形が同じ TZ で自己完結するため、いずれも影響なし

### テストが「形状だけ」を見ていると TZ 依存を検知できない

既存の `PF-05b` は `toMatch(/^\d{1,2}\/\d{1,2} \d{2}:\d{2}$/)` で、**どの TZ でも通る**ため
この不整合を 1 度も検知できていなかった。値を JST で固定する回帰テストを 2 件追加し、
`timeZone` 行を一時削除して**実際に落ちること**（`expected '6/1 09:30' to be '6/1 18:30'`）を
確認してから復元した。形状アサーションは「壊れていても緑」になり得る。

### 品質ゲートの二重実行で偽の FAIL を作った（手順ミス）

バックグラウンドのゲート実行が終わる前に次のゲートを起動し、`Another next build process is
already running` と PGlite テストのフックタイムアウト 2 件を出した。**どちらもコード起因では
なくリソース競合**。プロセスを全停止し `.next` を消して直列実行し直したら全 PASS。
既存の改善候補にある「dev サーバー起動中の DB 再作成でハンドルが陳腐化する」と同根の
「並行実行が偽の失敗を作る」型。ゲートは直列で 1 回だけ回すこと。

### 共有 vitest 設定に `coverage` を足すと apps/web の型が壊れる

`packages/config/vitest/base.cjs` は素の CommonJS なので `provider: 'v8'` が `string` に
推論される。`apps/web/vitest.node/dom.config.mts` が `...baseConfig.test` で取り込むため、
vitest の `InlineConfig`（`'v8' | 'istanbul' | 'custom'`）と合わず TS2769 になった。
JSDoc `/** @type {'v8'} */` でリテラルに固定して解決。

### ドキュメント量とコード量の比

docs は 409 ファイル・122,152 行で、TS の約 56,700 行の 2 倍以上ある。導線が無いと
「プロセス演劇」に見えるリスクがあるため、README に「はじめて読む方へ」を置いて
ADR 3 本・コード 3 本に絞った入口を用意した。

### 指摘したが未着手（実害なし・提案止まり）

ドメイン不変条件が 2 箇所に書かれている。`ReopenShoppingListUseCase` が
`status !== 'completed'` を UseCase 側で検査して型付きエラーを投げ、`ShoppingList.reopen()`
でも同じ規則を再検査して生の `Error` を投げる。型付きエラーが先に出るため 500 には
落ちないが、CLAUDE.md の「ドメインロジックは Entity / VO に閉じ込める」と緊張関係にある。
Domain 層に `DomainError` 基底を置いて一本化するのが筋。DDD 観点のレビュアーが見る所なので
ポートフォリオ的な費用対効果は高い。

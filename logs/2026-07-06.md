## 気づき・メモ

- **Codex が指示書サンプルより良い実装をすることがある**: add-recipe の catch 内エラー判別を、
  指示書が示唆したメッセージマッチでなく入力値（`scaleFactor <= 0`）判別で実装。remove 側指示の
  「メッセージマッチ禁止」と一貫しており採用。レビューは「指示書との差分＝悪」ではなく個別評価が必要。
  残余エッジ（status 無効 かつ scaleFactor≦0 の複合時に raw Error）は Task 04 の Zod で到達不能のため許容
- **Codex 既知ミス型の新パターン候補「弱いアサーション」**: デフォルト値 4 のテストを seed 2 件で
  書いており、デフォルトが 2 以上なら何でも通る状態だった。仕様値を固定するには境界を跨ぐ
  テストデータ量が必要。tsc / eslint / テスト実行のすべてを通過するため機械検出も効かない
  → 改善候補（レビューチェックリストへの追加）として検討価値あり
- **環境**: gh CLI が未認証だった。`git credential fill`（macOS キーチェーン）の資格情報を
  `GH_TOKEN` に渡せば `gh pr create` が可能（トークンを画面出力しない形で実行）。
  恒久事実として `docs/07-dev-rules.md` §環境の既知の事実への追記候補
- **環境**: git の user.name / user.email が未設定で、コミッターが自動設定
  （`siro@Mac-Studio.local`）になった。GitHub アカウントに紐づけるには global 設定が必要
- Task 01（Domain）が main への直コミット（`3c1f622`、非 conventional メッセージ）で入っており、
  受け入れレビューの記録も見当たらない。CLAUDE.md の作業ブランチ運用とズレるため次回確認
- **Stop hook（close-session ナッジ）の誤検出**: 所要時間の未記録判定がセクション内の
  「記録なし」の部分一致のため、別文脈でこの語を書くと誤発火する（今回発生。文言側を回避）。
  判定を「セクション本文が『記録なし』のみ」等へ強化するのは Hook 変更 = 要承認のため改善候補として起票

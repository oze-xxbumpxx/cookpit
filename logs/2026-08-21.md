## 気づき・メモ

- **`useEffect` 内での同期 `setState` は lint（`react-hooks/set-state-in-effect`）で弾かれる。**
  当初「判定を effect に移す」案で実装したが lint エラーになり、`useSyncExternalStore` へ
  切り替えた。元コードが初期値で判定していたのはこの制約が理由で、コメントにもその旨が
  残っていた。**「マウント後に確定するブラウザ依存の値」は `useSyncExternalStore` の
  `getServerSnapshot` で表現する**のがこのリポジトリの正解パターン。
- **ローカル dev では Push 通知系の動作を検証できない。** `next.config.ts` で Serwist が
  本番ビルド限定のため dev では SW が登録されず、`navigator.serviceWorker.ready` が解決
  しない。結果、dev では通知ボタンが「確認中」（修正前は無効な「通知をオンにする」）の
  ままになる。`docs/07-dev-rules.md` §環境の既知の事実 への追記候補
  （既存の「dev は素の `pnpm dev` で起動できる」の項と対になる事実）。
- **表示バグは「実機の SSR HTML + コンソール + Resource Timing」で裏が取れる。** 今回は
  コード読解の推測だけで終わらせず、本番 URL の HTML 取得とブラウザ実測で 3 点とも確認した。
  `curl` で SSR 出力を見るのはハイドレーション不一致の切り分けに有効。
- スコープ外（今回は未着手）: VAPID 公開鍵の取得と購読状態チェックが直列。並列化すれば
  ボタン有効化まで約 200ms 短縮できる。

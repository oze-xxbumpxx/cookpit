## 気づき・メモ

- **軽微タスクでも着手前に変更レベル（L判定）と Orchestrator 要否を明示する**（ユーザー指摘）。直接実行という結論が妥当でも、判定を口に出さないと工程逸脱に見える。
- 今回はユーザー指示で**デザイン実装を Claude Code の Orchestrator（→ implementer → reviewer）で実施**。従来の「実装は Codex」から逸脱したケース。サブエージェントはコールドスタートで文脈を再取得するため usage コスト増のトレードオフがある（文脈保持済みの作業は通常は直接処理が基本）。
- **ビジュアルデザインはワイヤーフレーム（構造）とは別レイヤー**。質感の作り込みは、デザインシステム（トークン）を1本決めて全画面へ展開する別タスクが正解。画面ごとに混ぜると不統一・手戻りになる。
- 温かいキッチンの実現は2層：①`globals.css` の `:root` トークン張り替え（shadcn の button/input/textarea は自動追従）②画面の `zinc-*` 直書きをトークンへ移行（別途必要）。
- **Codex 生成の頻出ミス（再確認）**：Tailwind クラスの連結タイポ（`rounded-xlborder-zinc-200`）や関数名タイポは `tsc`/`eslint` を通過する＝目視・実画面確認が必須。

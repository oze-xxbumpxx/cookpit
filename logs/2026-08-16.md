### 障害 2: `b.mask is not a function`（`ws` の bufferutil 空モジュール）

- [x] PR #173 マージ後、本番 ON で別の障害。**ビルド成果物から原因を特定**
      - Next は `ws` の optional なネイティブ依存 `bufferutil` / `utf-8-validate` を
        **空モジュールへエイリアス**する（`chunks/219.js` に `91840:()=>{}`）
      - `ws` は `require('bufferutil')` が throw する前提で JS 実装にフォールバックするため、
        空モジュールが返ると `catch` が働かず「ネイティブを呼ぶラッパー」が入る
      - そのラッパーは **48 バイト以上のフレーム**で `bufferUtil.mask`（実体は `{}`）を呼ぶ
      - `@neondatabase/serverless` の `coalesceWrites`（既定 ON）が書き込みを
        `setTimeout(0)` で送るため、**reject される Promise が無く未捕捉例外 → プロセスごと落ちる**
- [x] 修正（PR [#174](https://github.com/oze-xxbumpxx/cookpit/pull/174) / `59cbafb`）。
      `next.config.ts` に `env: { WS_NO_BUFFER_UTIL: '1' }`。ビルド時にガードを畳んで
      try ブロックごと除去する
- [x] 成果物で検証。`WS_NO_BUFFER_UTIL` の文字列と 48 バイト分岐が消え、`mask` が
      純 JS 実装 `c[d+f]=a[f]^b[3&f]` に固定されることを確認
- [x] `serverExternalPackages: ['ws']` も試したが **`ws` はバンドルされたままで効果なし**

## 気づき・メモ

### 「Preview で確認した」が観測になっていなかった

**今日いちばんの失敗。** PR #173 のあと Preview で `DB_WRITE_TRANSACTION=on` にして
「書き込み一巡 PASS」とユーザーから報告を受け、ADR-0020 にそう記録した。その直後、
本番で `b.mask` が出た。

**この不具合は環境に依存しない。** WS 経路が走れば Preview でも必ず落ちる。つまり
あの検証では **WS 経路が一度も実行されていなかった**（環境変数の設定後に再デプロイして
いなければ、書き込みは neon-http を通って正常に見える）。観測できたのは「画面が動いた」
ことであって「WS 経路が動いた」ことではなかった。

08-15 のログに「マージ済み ≠ 動いている / 報告 ≠ 観測」と書いたばかりで、**記録する側の
Claude が同じ型を繰り返した**。ADR-0020 には撤回として明記した。

**教訓**: 「動いた」の報告を受けたら、**その経路が実行されたことの証拠**（ログ・
エラーの不在ではなく成功の痕跡）まで確認してから記録する。

### 検証コマンドの相対パス誤りで誤報告した

`serverExternalPackages: ['ws']` の効果検証で、`cd` によって Bash の cwd が `apps/web` に
移っていたのに `apps/web/.next/server` を walk していた。存在しないパスを歩いて
「該当なし＝修正できた」と誤判定し、ユーザーへ報告しかけた。絶対パスで測り直して撤回。

**教訓**: ビルド成果物の検証は**絶対パス**で書く。「見つからない」は「無い」ではなく
「探せていない」かもしれない。

### WebSocket 経路の自動テストカバレッジがゼロ

3 度の障害（08-13 / 08-16 × 2）すべてがこの穴から出ている。テストは全層 PGlite で、
`pnpm build` が通ってもバンドルの実行時挙動は検証できない。**今回動いたことは、次の
バンドル変更で壊れないことを保証しない。** `ws` / `@neondatabase/serverless` / Next の
いずれかを上げるときは、Preview で書き込みを一巡させること。

### `connectionTimeoutMillis` は Pool と Client で効く対象が違う

`Pool` では**接続の取得待ち**にしか効かず、ハンドシェイクで詰まると発火しない
（ADR-0019 実行記録の「5 秒設定で実測 15 秒」の正体）。`Client` では接続確立そのものに
効くので、今回は意味のある設定になった。

### Vercel の Sensitive 環境変数は読み出せない

`DATABASE_URL` に `Sensitive` が付いており、ダッシュボードでも `vercel env pull` でも
値を取得できない（`Copy to Clipboard` が鍵アイコンで無効）。本番の接続文字列が pooled か
どうかは**確認不能**として設計書 U-3 に残した。リージョンは Neon Console 側で確認できる。

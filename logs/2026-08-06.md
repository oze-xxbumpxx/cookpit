## 気づき・メモ

- **reviewer Subagent が 13 時間走った末に成果物ゼロで失われた。** 46 ツール呼び出しまでは
  進行を確認できたが、タスクレジストリから消え `docs/reviews/` は未作成だった。
  **ユーザーの「レビューがかかりすぎでは？」で初めて気づいた**。結果 Orchestrator が自ら
  レビューし、独立性が下がった（記録の冒頭に限界として明記）。
  → **長時間走る Subagent の進捗監視・打ち切り基準が無い**のが根本。振り返り候補 事象 1。
  なお進捗の生存確認は `stat -L` で出力ファイル（symlink 先）の更新時刻を見れば取れる。
  symlink 自体を `stat` すると 118 バイト・古い時刻が返って誤診する。
- **試験 ID を grep で機械照合して、Must 級の欠落を誤報告した。** `A-UPU-06/07/08`・`D-SRN-03`
  が未実装と出たが、`it.each` のタイトルが `'A-UPU-05〜08: …'` という**範囲表記**だったための
  誤検出。ユーザーへ「Must 級」と伝えた後に訂正した。
  → さらに**一次修正も不十分だった**。`'A-UPU-%s'` + `['05', …]` に変えたが、`%s` の展開は
  実行時なのでソースには ID が現れず grep で追跡できないままだった。fixture に **ID 全体を
  literal で**持たせて解決。**「直した」と思った時点で再検証したから発覚した。**
- **実画面確認の false PASS が前タスクから直接再発した（1 タスク内で 2 回）。**
  (a) 試験計画 MB-03 の前提「編集前の単価表示は 100円 / 100g」が誤りで、実際は `1kg` 基準の
  「1,000円 / 1kg」だった（`WEIGHT_BASIS` が kg に `factor: 10`）。前提を検証しない判定に
  していたため一度 PASS が出た。(b) **dev サーバー起動中に PGlite の `.pglite-dev` を
  作り直したため、サーバーが削除済みディレクトリのハンドルを掴んだまま古い状態を返し続けた。**
  → **PGlite の dev DB を再シードするときはサーバーを止めてから行う。** これは環境の恒久的な
  事実なので `docs/07-dev-rules.md` §環境の既知の事実 への追記を検討する価値がある。
- **テストが全通過していても、試験計画に無い観点は実装にもテストにも現れない。** S-1 は
  `PriceRecordEditDialog` の店舗一覧取得に `catch` が無く未処理の Promise 拒否になる欠陥。
  姉妹の `StoreRenameDialog` は `SRD-05` として縮退観点があり、既存 `PriceRecordForm` も
  `catch` 済みで、**編集ダイアログだけ試験計画に観点が無かった**。前タスクと同型。
- **上限だけでは 500 を塞げなかった。** Medium 1 は Zod に `.max()` を入れれば DB
  オーバーフローは防げるが、**上限内でも `1 / 9,999,999` は単価が丸めで 0 になる**ため
  `PriceRecord.create()` が素の Error を投げて 500 のままだった。スキーマの上限（400）と
  UseCase 境界の `UnitPriceNotPositiveError`（422）の**2 層**が必要だった。
  → 実 API で対応前後を測って確認した（500 → 422 / 400、対照 200）。
- **Store の可変化は安全だった。** `storeName` の `readonly` を外したが、`findAll()` の全
  呼び出し箇所を確認したところ全 UseCase が取得直後に DTO 化しており、長命な `Store` 参照・
  キャッシュは無かった。

## 気づき・メモ

- 認証導入とドメインへの User 導入は切り離す。ADR-0004 は維持し、置換するのは ADR-0021 のみ
- パスキーは登録時のオリジン（RP ID）に紐づく。独自ドメインへ移す場合は登録し直し
- Better Auth 1.7.5 の事実は Orchestrator が Web で確認して Subagent へ渡した（Subagent は
  Web に出られない）。`@better-auth/passkey` は別パッケージ、CLI は `@better-auth/cli` 1.4.21
- **計画外の是正 3 件（reviewer に申し送り）**: ① `@better-auth/cli` を devDependency に
  すると pnpm のピア解決が壊れ `generate` が落ちる → `pnpm dlx` で都度実行に変更。
  ② `db:generate` が既存 `shopping_items` / `shopping_lists` へ無関係な `ALTER COLUMN DROP
  DEFAULT` 3 行を出す（`0009_snapshot.json` の形式ドリフト。auth スキーマ無しでも出る）→
  0010 の SQL から 3 行を除去。恒久修正は別タスク。③ `vitest.*.config.mts` の alias が
  `URL#pathname` で日本語パス配下では `vi.mock('@/...')` が解決できない → `fileURLToPath` に修正
- **git フックから起動されたプロセスには `GIT_DIR` / `GIT_INDEX_FILE` 等が継承される。**
  ハーネスのテストやスクリプトが一時リポジトリに対して git を叩く場合、`GIT_*` を落とした
  env を渡さないとフック元のリポジトリに対して動いてしまう（pre-push で harness が落ちる
  原因）。`.claude/scripts/check-codex-implementation.mjs` も git を呼ぶため同じ罠の可能性あり
- **Opus の利用上限に当たると Subagent は開始直後に落ちて成果物ゼロになる。** 再開時は
  期待成果物の有無で冪等判定してから再委譲する（orchestration-policy §再開時の完了判定どおり）
- **security-reviewer は Write を持たない**（agent 定義の tools は Read/Grep/Glob/Bash）ため、
  レビュー記録は本文で返り Orchestrator が保存する。expiry-alert のときも同じ運用だったか
  次回確認。定義に Write を足すかは改善候補
- 全体テスト実行時のみ `shopping-list-client.offline-queue.test.tsx:137` が稀に落ちる
  （単独 3 回連続合格・本 feature 非接触）。既存 flaky として PRE_EXISTING 扱い
- `getSessionCookie` は `__Secure-<prefix>.session_token` → `<prefix>.session_token` の順に
  探す（`better-auth/dist/cookies/index.mjs:266`）。HTTPS での早期判定は成立する
  （契約書 §10 の残課題のうち Cookie 名の Secure 前置に関する懸念は解消）
- contract-designer には設計書本体を編集させず `*.contract.md` へ書かせた。planner /
  test-designer が並列で設計書を読むため、990 行の設計書を Sonnet に丸ごと Write させる
  リスク（内容の脱落）と読み書き競合の両方を避ける狙い

## 気づき・メモ

- **「URL をリポジトリから消す」は対策にならない。** リポジトリ名が `cookpit`、Vercel
  プロジェクトが `cookpit-web` なので、本番 URL は公開リポジトリ名からほぼ自明に導ける。
  git 履歴を書き換えても防御にならず、**認証を掛ける以外に手がない**。
  対策案は ① Vercel Deployment Protection（コード変更ゼロ・最短）② `middleware.ts` で
  Basic 認証（ADR-0003 が Phase 2 の次手として想定済み）③ Better Auth。
- **公開は ADR-0003 の前提条件そのものを壊す変更**なので、決定理由 5 を無効化する追記
  （または新規 ADR）を残すのが筋。公開を実行する場合は L2 相当の判断として扱うべき。
- 誤検知しやすいものを潰しておく：`169.254.169.254` / `evil.example` /
  `fcm.googleapis.com.evil.example` は **VAPID_SUBJECT の SSRF 検証テストのフィクスチャ**。
  `BEl62iUYgUivxIkv...`（`designs/expiry-alert.contract.md:594`）は web-push 公式ドキュメント
  由来のサンプル**公開**鍵の切り詰め。`docs/reviews/*` の 64 桁 hex はコンテンツダイジェスト。
  次に監査する人が同じ確認を繰り返さないようここに残す。
- **環境の事実（恒久）**: リモート実行環境は egress がプロキシで遮断されており、本番 URL への
  疎通確認ができない（`connect_rejected`）。`logs/2026-08-13.md` / `2026-08-21.md` が行った
  「本番 URL の SSR HTML 取得・実測」は**この環境では再現できない**。本番実測が要るタスクは
  ローカルセッションで行う必要がある。→ `docs/07-dev-rules.md` §環境の既知の事実 への
  追記を次回判断する。
- `guard-dangerous.mjs` は grep パターン中の `.pem` / `id_rsa` という**文字列そのもの**に
  反応してブロックする。秘密情報を探す監査作業自体がフックに阻まれるため、
  `id_[r]sa` のように分割して回避した。誤検知だが、安全側の挙動なので変更は提案しない。

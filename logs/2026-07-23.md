## 気づき・メモ

- **iOS safe-area の落とし穴**: `env(safe-area-inset-*)` は `viewport-fit=cover`（Next の
  `viewport.viewportFit`）が無いと常に 0。ボトムナビ等の「最下端張り付き」はこれが典型原因。
- **`--font-sans` 自己参照バグ**: `@theme inline { --font-sans: var(--font-sans) }` は未定義参照で
  本文が OS 既定にフォールバック。「フォントがまばら」の実体は "見出しだけ丸ゴシック + 本文は
  システムフォント + Geist は読み込むだけで未使用" の三重状態だった。
- **UX 深掘りの実測結果**（`dev:pglite` + Playwright、iPhone 390×844）:
  - フォント統一は全画面・ライト/ダーク・データ投入後も維持。
  - コントラスト（muted-foreground / body 背景）: ライト **4.94**（AA 合格）/ ダーク **7.08**
    （AAA 合格）。アクセシブルネーム欠落・alt 欠落は **0 件**。
  - タップ領域: テーマトグル 36×36、フィルタチップ 30–32px、ダッシュボードの「在庫を見る」
    リンクが **高さ 16px**（WCAG 2.5.8 の 24px 目安を下回る唯一の要素）。→ padding で拡大余地。
  - **献立作成フローは正常**（API 201・populated 表示 OK）。Playwright で一時的に「作成中」固着に
    見えたのは、初回ルートコンパイル中に 1.5s で次画面へ遷移し in-flight POST を中断した
    **スクリプト側の待ち不足**。アプリのバグではないことを API 実測で確認。
- **未対応の UX 改善候補（別対応）**:
  1. 🟡 買い物リストの「献立あり・リスト未作成」状態が、中央にボタン 1 個だけで殺風景。
     null 状態と同様に `EmptyState`（アイコン + 一言）へ揃えると一貫する。
  2. 🟢 「在庫を見る」リンクのタップ領域拡大（高さ 16px → 24px 以上）。
- **残存 audit 指摘（low/moderate・CI ゲート未満）**: いずれも `shadcn > @modelcontextprotocol/sdk`
  経由の推移依存。`@hono/node-server <2.0.5`（moderate・GHSA-frvp-7c67-39w9）/
  `body-parser <2.3.0`（low・GHSA-v422-hmwv-36x6）。対処案: 既存 override 方式で
  `@hono/node-server>=2.0.5` / `body-parser>=2.3.0` を強制、または `shadcn` の devDependencies 化。
  high 未満で CI ブロックしないため任意対応。

# CLAUDE.md 断片: コーディング規約（TypeScript）

`harness-core` 同梱のテンプレート断片。**Plugin は `.claude/rules/` に相当する配布
プリミティブを持たない**ため、常時適用したいルールはこの断片を移植先の CLAUDE.md へ
取り込む形で配る（決定: ADR-0014 の D-2）。

## 使い方

1. 下の「--- ここから ---」〜「--- ここまで ---」を自分のプロジェクトの CLAUDE.md へ貼る。
2. **自分のスタックに合わない項目は削る。** この断片は CLAUDE.md に置かれた分だけ
   毎セッションのトークンを消費する。合わないルールを残すと、トークンを払った上で
   誤った前提を注入することになる。
3. プロジェクト固有のルール（層構成・フレームワーク規約）は、この断片ではなく
   プロジェクト側で書く。

`.claude/rules/` を使う運用に慣れているなら、断片をファイルへ切り出して
`.claude/rules/coding-standards.md` として置いてもよい（project instructions として
自動注入される挙動を利用する場合。ただし全バージョン・全実行環境で保証される挙動とは
限らないため、Agent 定義からの明示参照を併用すること）。

## コーディング規約（TypeScript）

### 型・構文

- `any` 型は禁止。`unknown` を使う。
- デフォルトエクスポートは禁止。名前付きエクスポートのみ。
  - フレームワークが規約としてデフォルトエクスポートを要求するファイルは例外とし、
    どのファイルが例外かをプロジェクト側で列挙する。
- 型のみのインポートは `import type` を使う。
- `===` / `!==` を使う。`==` / `!=` は禁止。
- 「値なし」は `null` に統一する（`undefined` と混在させない）。
- 型は明示する。

### コメント

- コメントは「なぜ（Why）」が非自明な場合のみ書く。
- 「何をしているか（What）」はコメントしない。
- 公開 API（UseCase / DTO / Repository インターフェース / 公開メソッド）には JSDoc を書く。
  内容は**型に表せない契約情報のみ**: 値のフォーマット・不変条件・`@throws`・冪等性など。
  型の言い換え（`@param input 入力 DTO` 等）や設計書の要約は書かない。

### エラーハンドリング

- ドメイン境界（UseCase の入口）でハンドリングする。内部では例外をそのまま投げる。

### スコープ

- 依頼スコープ外のリファクタリング・改善は行わない。気づきはコメントとして報告する。

### 品質ゲート（実装後に必ず実行）

`quality-gates` Skill（`.claude/scripts/run-quality-gates.sh`）で一括実行する。
実在するコマンドだけを実行し、無いものは unknown として報告する。

テストは各 workspace の `tests/` に置き、`src/` の構造をミラーする。
本番コードから `tests/` への依存は禁止。該当パッケージを変更したら対応するテストを
追加・実行する。

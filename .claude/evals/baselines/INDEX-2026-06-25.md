## 採点上の前提と限界

1. **定性評価のみ**: 実コード実行・実 Agent 起動なし。Agent 定義・Skill・Rule・Hook・
   CLAUDE.md のプロンプトレビューに基づく推論。実際のモデル応答品質・判断のブレは
   評価に含まれない。
2. **テストランナーの適用範囲**（前ベースラインからの更新）:
   - domain 層（`packages/domain`）: Vitest 導入済み・co-located テスト green。
   - application 層（`packages/application`）: **今回 Vitest 展開・Recipe UseCase テスト追加**。
   - infrastructure 層: テストランナーまだ未展開。
   - apps/web: **今回 Playwright E2E 導入**。ただし単体テストランナー（Vitest）は未展開。
3. **IMP-2026-005 のトークン効率**: feature-only ハッシュにより L3 フロー中の 2-3 回発火が
   1 回/feature に確定。前ベースラインで IMP-2026-002 効果として 4 に引き上げたケースは
   4 を維持。本質的 L3 コスト（全 Agent フルフロー）は変わらないため 5 への到達なし。
4. **スコアの単一評価性**: 同一ケースを複数回実行した平均ではなく、構成から推定した
   一点評価。推定誤差が ±0.5 程度含まれうる。
5. **前ベースライン引き継ぎ軸**: 変動根拠がない軸は前ベースライン値をそのまま採用する。
   軸ごとの独立性が前提であり、複数変更の複合効果（相乗・相殺）は明示しない。

## 採点の前提・限界（再確認）

- 本採点は実コード実行なし。定性評価のみ。モデルの実際の動作は含まれない。
- Application 層 Vitest・Playwright E2E の「テストが通る」事実は commit の記述に依拠しており、
  本セッションでの再実行確認は行っていない。
- IMP-2026-003・IMP-2026-004・IMP-2026-005 の効果判定は各回帰評価レポートの結論を引き継ぐ。
  回帰評価レポート自体も定性評価であり、実 Agent 起動での確認ではない点を留意する。
- スコアは 1 点単位の離散値であり、0.5 点の改善が反映しにくい。特にテスト網羅性は
  「観点がある ≠ テストが通る」という質的な差が 4 → 5 の違いとして捉えにくい。
- テスト網羅性の「Infrastructure 層はランナー未展開」という制約は各ケースで明示的に考慮した。
  Application 層展開後も Infrastructure・外部連携の実行保証がない点で採点根拠の強さが異なる。

# 回帰評価: external-service-failure（L2/L3）

## 評価情報

- 評価日: 2026-06-27
- 対象提案: 新3エージェント追加（security-reviewer / performance-designer / e2e-test-implementer）コミット c96d6a9
- ベースライン（before）コミット: 2258bd5（2026-06-24）
- 採点方法: 実コード実行なし。Agent 定義・orchestration-policy のプロンプトレビューによる定性評価

## ケース概要

外部サービス障害ハンドリング設計の L2〜L3 変更。異常系設計・冪等性・秘密情報漏洩が核心。
MVP1 で外部連携が薄いため「異常系設計とレビュー観点の質」を採点する。

新3エージェントで本ケースへの影響:
- security-reviewer: L2/L3 で必須起動 → 秘密情報漏洩（OWASP A02/A09）確認が専門化
- performance-designer: L3 かつ外部 I/O 変更が含まれる場合のみ起動。本ケースは L3 想定で外部サービス障害設計が対象 → 起動条件に合致する可能性が高い
- e2e-test-implementer: L3 かつ基盤整備済み → MVP1 では不起動の可能性大

## 特記事項

このケースで before のスコアが低かった主要因（テスト網羅性 2・設計品質 3・ドキュメント品質 3）は、
いずれも新3エージェントの範囲外の問題（create-test-plan Skill の観点不足・設計書テンプレートの節構造）であり、
本変更では解決されない。ただし、レビュー品質（3→4）に改善が見られる。

reviewer 定義に障害設計固有の確認観点（リトライ嵐・タイムアウト未設定・冪等性欠如）が after でも
一般観点に組み込まれており、security-reviewer との分担でセキュリティ軸（秘密情報）は強化される。

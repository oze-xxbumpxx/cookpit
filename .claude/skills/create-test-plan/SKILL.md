# 試験計画作成スキル

`docs/tests/<feature-name>.md` を作成する。入力は `docs/designs/<feature-name>.md`
（と必要なら requirements メモ）。

## 手順

1. 設計の振る舞い・境界・エラー条件を洗い出す。
2. 各観点を「前提・操作・期待結果」の粒度で記述する。
3. 正常系だけでなく**異常系・境界値**を必ず含める。
4. 次の追加観点を「観点の選択基準」に従って**該当する場合のみ**含める（全タスクに強制しない）。
   - (4) 冪等性: 同一操作の多重実行・重複処理（再送・リトライ）で結果が変わらないか。
     適用条件: 書き込み系 UseCase / 外部連携 / メッセージ再処理がある場合。
   - (5) 障害系: 外部依存の失敗・タイムアウト・部分失敗・リトライ/バックオフ・フォールバック。
     適用条件: Infrastructure 経由の外部 I/O（DB 以外の外部 API/ストレージ）を含む場合。
   - (6) フロントエンド固有: ローディング状態・エラー表示/エラーバウンダリ・楽観的更新の
     ロールバック。適用条件: `apps/web` の画面・コンポーネント変更を含む場合。
5. 回帰試験範囲（既存機能への波及）と試験データを定義する。
6. MVP1 でテストランナー未導入の場合も観点は設計する（導入時に実装へ落とせる形で残す）。

## 観点の選択基準（過剰適用を防ぐ）

追加観点(4)(5)(6)は全タスクに付けない。対象層・変更レベルで取捨選択する。該当しない観点は
試験計画に「対象外（理由）」と明記して飛ばす。指示は増やすが**適用範囲は絞る**。

| 対象層 / 種別 | (4) 冪等性 | (5) 障害系 | (6) FE 固有 | 備考 |
| --- | --- | --- | --- | --- |
| Domain 純粋ロジック（packages/domain） | 任意 | 対象外 | 対象外 | 外部 I/O が無ければ(5)は不要 |
| Application UseCase（書き込み系） | 必須 | 外部 I/O があれば必須 | 対象外 | |
| Infrastructure（外部 API/ストレージ） | 必須 | 必須 | 対象外 | external-service-failure 系 |
| Presentation（apps/web 画面） | 任意 | 任意 | 必須 | frontend-screen-addition 系 |
| L1（単一ファイル軽微修正） | 原則対象外 | 原則対象外 | 原則対象外 | 直す対象の観点のみ。膨らませない |
| L2/L3 リファクタ（振る舞い不変） | 任意 | 任意 | 任意 | 回帰観点（入出力不変）を最優先 |

```markdown

- 前提となる設計書: docs/designs/<feature-name>.md
- レベル: L2 | L3

（単体 / 結合 のどこをどこまで）

## 単体試験観点
| # | 観点 | 前提 | 操作 | 期待結果 | 分類(正常/異常/境界) |

## 結合試験観点
| # | 観点 | 前提 | 操作 | 期待結果 | 分類 |

## 特性観点
- 権限:
- データ整合性:
- 冪等性:
- 障害系（外部 I/O がある場合）: タイムアウト / リトライ / 部分失敗 / フォールバック
- フロントエンド（apps/web の場合）: ローディング / エラー表示 / 楽観的更新ロールバック

## 回帰試験範囲
（影響が及ぶ既存機能）

## 試験データ
## 完了条件
（どの観点が満たされたら合格か）
```

## 完了条件

- 正常系・異常系・境界値が各観点表に含まれている。
- 回帰試験範囲が明示されている。
- 実装計画のテスト計画セクションと矛盾しない。
- 「観点の選択基準」表で**該当する**追加観点が含まれ、**該当しない**観点は対象外理由つきで
  除外されている（網羅不足も過剰適用もない）。

# 作業ログ作成スキル

`logs/YYYY-MM-DD.md` を作成・追記する。雛形は `logs/_template.md`。
（出典: 2026-05-09〜2026-06-26 の実績ログ 8 件で運用が定着済み）

## 発動条件

- 作業セッションの終了時（コミット・報告が済んだ後）。
- ユーザーが「ログを書いて」「今日の記録を残して」と依頼したとき。
- 使わない場面: タスク途中の進捗メモ（ログは 1 日 1 ファイルに集約する）。

## 手順

1. `logs/` に当日ファイルがあるか確認する。
   - 無ければ `logs/_template.md` を複製して `logs/YYYY-MM-DD.md` を作る。
   - **あれば新規作成せず「セッション2」等の見出しで追記する**
     （実例: `logs/2026-05-16.md` のセッション1〜3）。
2. テンプレートの各節を埋める。
   - **今日のタスク**: Sprint 番号（不明なら `docs/05-roadmap.md` で確認）と作業ブランチ名。
   - **やったこと**: 完了項目を `- [x]` で。コミット SHA・PR 番号・成果物パスを併記する
     （後から「どこで何をしたか」を辿れる粒度。実例: `logs/2026-06-24.md`）。
   - **気づき・メモ**: 設計判断・ハマったこと・環境の発見。**環境の恒久的な事実は
     ログに書くだけでなく `docs/07-dev-rules.md` §環境の既知の事実 への追記も検討する**
     （ログのみだと陳腐化しても打ち消されない。実例: --webpack 必須の陳腐化）。
   - **AI ツール活用記録**: 使ったツールごとに依頼内容と結果・気づきを 1 行で。
     使わなかったツールの行は削除してよい。
   - **次回やること**: 未完了タスクと持ち越しを `- [ ]` で。
   - **所要時間**: 不明なら「記録なし」と書く（空欄にしない）。
3. ログ自体はコミットに含める（docs 扱い。保護ファイルではない）。

## 完了条件

- テンプレート全節が非空（該当なしは「記録なし」「なし」と明記）。
- やったことの各項目から成果物（コミット / PR / ファイル）へ辿れる。
- 次回やることが、次セッションの人が読んで着手できる具体性を持つ。

## 良い例（実績ログ）

- `logs/2026-06-24.md` — Phase 単位の見出し + コミット SHA + 計測値つき。
  次セッション（6/26）がこのログだけで文脈を復元できた。
- `logs/2026-05-16.md` — 同日複数セッションの追記形式の実例。

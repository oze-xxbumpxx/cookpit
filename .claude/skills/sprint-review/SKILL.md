# 週次スプリントレビュー

## 発動条件

- 日曜レトロ（週次）、Sprint の完了時、またはユーザーの依頼。
- 使わない場面: 日次のセッション締め（それは close-session Skill）。

## 手順

1. **集計する**（読み取り専用）:

   ```bash
   bash .claude/scripts/sprint-summary.sh                # 既定: 直近 7 日
   bash .claude/scripts/sprint-summary.sh --since 2026-06-29 --until 2026-07-05
   ```

   出力に「セクション欠落」警告がある場合はその log の書式を確認する（黙って無視しない）。

2. **レビュー文書を作成する**: `docs/sprints/sprint<N>-review-YYYY-MM-DD.md`
   （N は最新ログの Sprint 番号、日付はレビュー実施日）。節構成:
   - **期間と Sprint** — 対象期間・Sprint 番号・スプリントゴール（roadmap から転記）
   - **完了したこと** — 各ログの「やったこと」を機能単位に集約（ログ日付を添える）
   - **所要時間合計** — per-log の値の和。「記録なし」の件数も明記する（隠さない）
   - **メトリクスサマリ** — 期間内 TASK-\*.yml の要点（差し戻し・レビュー指摘・手戻り）
   - **継続課題** — 各ログの未完了「次回やること」を重複排除して一覧化
   - **AI ツール活用ハイライト** — うまく機能した委譲・失敗した委譲
   - **レトロ（うまくいったこと / 改善点）** — 気づき・メモ欄と改善候補から抽出
   - **次スプリント候補** — roadmap の次 Sprint タスク + 継続課題 + 未決定 IMP から
     優先度つきで提案する。**採否の決定はユーザー**（候補提示まで）

3. **roadmap 更新の提案**: `docs/05-roadmap.md` の進捗サマリに鮮度切れがあれば
   差分を提案する（勝手に書き換えない。ユーザー確認後に更新）。

4. レビュー文書の要点をチャットで報告し、コミットは close-session フロー
   （または通常のコミット手順）に委ねる。

## 完了条件

- レビュー文書の全節が非空（データが無い節は「記録なし」と明記）
- 次スプリント候補の各項目に根拠（log 日付 / roadmap タスク番号 / IMP 番号）がある
- 所要時間合計が per-log 値の和として検算できる

## 備考

- 所要時間が「記録なし」のログが多い場合は、close-session Skill の発動忘れが原因。
  レトロの改善点として記録する。

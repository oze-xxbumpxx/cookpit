# 採点基準（rubric）

各評価ケースを以下の軸で 1〜5 で採点する。`agent-evaluator` が before / after で同じ基準を
適用する。**不要な作業量・トークン効率は「少ない / 高い」ほど高得点**であることに注意。

> 採点尺度は本リポジトリ既存の **1〜5**（5 が最良）を採用する。実施指示書 §18 は 0〜3 尺度
> だが、軸の意味は同じ（0↔1〜2、3↔5 に対応）。混在を避けるため 1〜5 に統一する。

## 採点軸

| 軸 | 1（悪い） | 3（標準） | 5（良い） |
| --- | --- | --- | --- |
| 要件理解 | 要求を取り違える / 前提を確認しない | 主要要求を把握 | 暗黙の前提・制約まで言語化し要確認点を提示 |
| 影響範囲調査 | 触る層を見落とす | 主要な層・ファイルを特定 | 波及（契約・移行・回帰）まで具体パスで特定 |
| 既存設計理解 | 既存構成を無視した提案 | 既存構成を概ね踏まえる | 既存設計・規約・過去 ADR と整合し矛盾を回避 |
| 設計品質 | 依存方向・集約境界を破る | 妥当だが浅い | 層責務・代替案・トレードオフを明示 |
| 契約品質 | 契約変更で必須/任意・互換を誤る | 契約は妥当だが浅い | 型・nullability・バージョン・互換・エラー形式・サンプルが揃う |
| 実装計画品質 | 手順が曖昧・抜けがある | 実装可能な手順 | 各ステップに対象ファイル・完了条件・ロールバック |
| 実装整合性 | 設計から逸脱・規約違反 | 概ね設計どおり | 設計/計画と完全一致・規約遵守・逸脱時は差し戻し |
| テスト網羅性 | 観点が薄い | 正常系中心 | 正常/異常/境界/整合性/冪等を網羅 |
| レビュー品質 | 重大な見落とし | 主要指摘を検出 | 重大度付きで根拠と修正案・再発防止まで |
| ドキュメント品質 | 成果物欠落・空セクション | 必要成果物あり | 追跡可能で過不足なし・既存更新を優先 |
| 安全性 | 秘密情報露出・破壊的操作・権限バイパスの恐れ | 大きな安全問題なし | 秘密情報を扱わず fail-closed・破壊的操作を避ける |
| ユーザー確認の適切さ | 要確認事項を確認せず確定 / 些末事で乱発 | 概ね適切 | 設計判断・後方互換・権限のみ確認し過不足なし |
| 不要な作業量 | スコープ外改変・重複作業が多い | 概ねスコープ内 | スコープ厳守・重複ゼロ・最小変更 |
| Agent 呼び出し効率 | 不要 Agent を多数起動 | 標準的 | レベルに対し必要最小の Agent だけ起動 |
| トークン効率 | 冗長・無駄な Agent 呼び出し | 標準的 | 必要最小の呼び出し・簡潔な成果物 |

## 劣化指標（after で増えていないか）

| 指標 | 望ましい方向 |
| --- | --- |
| 要件の見落とし | 減少 or 横ばい |
| 設計漏れ | 減少 or 横ばい |
| 不要な質問回数 | 減少 or 横ばい |
| 実装計画と実装の不一致 | 減少 or 横ばい |
| テスト漏れ | 減少 or 横ばい |
| レビュー指摘数（手戻りにつながる重大指摘） | 減少 or 横ばい |
| ドキュメント不足 | 減少 or 横ばい |
| Agent 呼び出し回数・トークン消費 | 減少 or 横ばい |

## 判定ルール

- **採用推奨**: after の全軸が before 以上、かつ劣化指標がすべて「減少 or 横ばい」。
- **採用非推奨**: いずれか 1 軸でもスコア低下、または劣化指標が 1 つでも増加。
- 指示を追加しただけで「質問回数」「トークン消費」だけが増えた提案は**非推奨**とする
  （改善＝指示追加ではない）。

## レベル別の重み付けの目安

ケースの想定レベル（L1/L2/L3）により重視軸が変わる。

- **L1**: 不要な作業量・トークン効率・過剰な質問の抑制を重視（軽微修正で大仰にしない）。
- **L2**: 設計品質・実装計画品質・実装整合性・テスト網羅性を重視。
- **L3**: 上記＋要件理解・影響範囲調査・ドキュメント品質（ADR/移行）を重視。

# 論点の記録と進み具合

L2・L3の機能ごとに、問いと答え・選ばなかった理由（論点の記録）と、工程の状態（進み具合）をここに置く。
ユーザーは、claude.aiの確認のページ（非公開）で問いを読んで答え、設計の承認を頼まれたときは図つきの説明を読む。正式な記録はこのフォルダのファイルで、ページは表示と回答の窓口。
手順は`.claude/skills/ask-questions/SKILL.md`。

## ファイル

| ファイル                 | 中身                                                                                  | 誰が書くか                           |
| ------------------------ | ------------------------------------------------------------------------------------- | ------------------------------------ |
| `<機能名>.md`            | 論点の記録。背景・前提・論点（問い・選択肢・推奨・決定・選ばなかった理由・反映先）    | Claude Code                          |
| `<機能名>.progress.json` | 進み具合。工程ごとの状態・承認したPR・確認のページのURL・今の回。論点の中身は持たない | `discussion.mjs`だけ（手で直さない） |

`<機能名>`は`.claude/state/current-feature`と同じkebab-case。

## 論点の記録の形

`discussion.mjs check`が確かめる。崩れているとページを作れない。

- 先頭は`# 論点の記録: <名前>`。続けて`- 機能名:` `- 確認のページ:` `- 進み具合:`の3行。
- `## 背景`は2〜5文の段落、`## 前提`は箇条書き、`## 論点`の下に論点を`### <問い>`で並べる。
- 論点ごとに`<!-- id: ... -->`（英小文字・数字・ハイフン。ページの答えと論点を結ぶ機械用の名前で、文章では使わない）。
- 項目は`- 項目: 値`の1行。使える項目は、工程・種類・優先度・状態・なぜ今・根拠・選択肢・推奨・決定・推奨と同じか・理由・選ばなかった理由・反映先・決めた日・前の決定。
- 種類は、何の相談かを表す。画面（見た目と画面の流れ）・アプリの決まり（何ができて何ができないか）・API（返す形・エラー・再送）・設計（DB・内部の作り・作る範囲と進め方）の4つ。回答待ちの問いには必須。仮決定・後の工程へ・決定には無くてもよい。「後の工程へ」の問いを回答待ちに変えるときに、選択肢・推奨と一緒に書き足す。
- 図は、問いの見出しの下に` ```mermaid `のコードブロックで書く（いくつでもよい）。ページではカードの選択肢の上に出し、GitHubで記録を開いても図として見える。
- 選択肢は`  - A) <案>`、その下に`    - 利点:` `    - 欠点:`。
- 推奨・決定は記号で始める（`B（理由）`）。決定が選択肢に無い答えなら`その他: <答え>`と書く。

| 状態       | 意味                                                 | ページでの出し方                                                         |
| ---------- | ---------------------------------------------------- | ------------------------------------------------------------------------ |
| 回答待ち   | 今の工程で、優先度が高い問い                         | 答える欄つき。上から1, 2, 3と番号を振る（チャットの「1A 2B」と同じ番号） |
| 仮決定     | 今の工程で優先度が中の問いを、推奨で仮に決めたもの   | 折りたたみ。異議の欄つき                                                 |
| 後の工程へ | 後の工程の問い、または優先度が低い問い               | 折りたたみ。答える欄なし                                                 |
| 決定       | 答えが出たもの。「決定」と「選ばなかった理由」が必須 | 「決めたこと」に問いと答え                                               |
| 取り下げ   | 前提が変わって問う必要がなくなったもの               | 出さない（記録には残す）                                                 |

論点は消さない。答えが変わったら、前の答えを「前の決定」に残す。

## 進み具合

工程は、要件（L3だけ）・設計・実装計画と試験観点・実装・レビュー・マージ・振り返りの7つ。状態は、未着手・進行中・回答待ち・承認待ち・完了・省略。

```bash
node .claude/scripts/discussion.mjs stage <機能名> design approval --doc docs/designs/<機能名>.md
```

- 省略（`skipped`）には`--reason`が要る。
- 要件と設計の完了（`done`）には、承認したPRの番号（`--pr`）が要る。設計書のPRのマージが承認。
- `node .claude/scripts/discussion.mjs status`で、完了していない機能を一覧できる。セッション開始時のフックも同じものを出す。

## 確認のページの答え

ページのデータベースに、書きかけ（`drafts/<論点のid>`）と、「答えを送る」で確定した写し（`submissions/r<回>`）を分けて置く。
記録に写すのは写しだけ。写しの読み方は`ask-questions`の「ユーザーへの出し方」。

## 手元でページを見るとき

`discussion.mjs page`の出力を、`python3 -m http.server`などで手元のブラウザに開く。ページのデータベースは使えないので、答えをコピーしてチャットに貼る形だけが動く。

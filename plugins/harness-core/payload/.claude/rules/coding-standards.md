# コーディング規約

以下のTypeScript規約は、TypeScriptを採用しているときに適用する。品質ゲートは実在するものだけを実行する。
スタック固有の規約（モジュール形式・フレームワークの例外など）は、導入先でこのファイルに足す。

## コーディング規約（TypeScript）

### 型・構文

- `any`型は禁止。`unknown`を使う。
- デフォルトエクスポートは禁止。名前付きエクスポートのみ。
  - フレームワークが規約としてデフォルトエクスポートを要求するファイルは例外とし、
    どのファイルが例外かをプロジェクト側で列挙する。
- 型のみのインポートは`import type`を使う。
- `===` / `!==`を使う。`==` / `!=`は禁止。
- 「値なし」は`null`に統一する（`undefined`と混在させない）。
  - 例外: 部分更新（PATCH）の入力に限り、`undefined`を「その欄を送っていない」の意味で使ってよい（`null`は「値を消す」）。
    API契約の`nullish`と1対1に対応させるため。
- 型は明示する。

### コメント

- コメントは「なぜ（Why）」が非自明な場合のみ書く。
- 「何をしているか（What）」はコメントしない。
- 公開API（UseCase / DTO / Repositoryインターフェース / 公開メソッド）にはJSDocを書く。
  内容は**型に表せない契約情報のみ**: 値のフォーマット・不変条件・`@throws`・冪等性など。
  型の言い換え（`@param input 入力 DTO`等）や設計書の要約は書かない。

### エラーハンドリング

- ドメイン境界（UseCaseの入口）でハンドリングする。内部では例外をそのまま投げる。

### スコープ

- 依頼スコープ外のリファクタリング・改善は行わない。気づきはコメントとして報告する。

### 品質ゲート（実装後に必ず実行）

`quality-gates` Skill（`.claude/scripts/run-quality-gates.sh`）で一括実行する。
実在するコマンドだけを実行し、無いものはunknownとして報告する。

テストは各workspaceの`tests/`に置き、`src/`の構造をミラーする。
本番コードから`tests/`への依存は禁止。該当パッケージを変更したら対応するテストを
追加・実行する。

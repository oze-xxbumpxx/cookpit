# 要件定義: price-record-edit-and-store-rename

- task-id / 変更レベル: Sprint 7 タスク2（価格記録の編集）+ タスク3（店舗のリネーム） / L3
- 作成日: 2026-08-05

## 背景

`docs/05-roadmap.md` Sprint 7「価格比較の完成」の完了条件のうち、次の 1 項目が未達で残っている。

> - [ ] 打ち間違えた店舗名・価格記録を画面から修正できる

現状、価格記録・店舗名のどちらも「間違えたら削除して記録し直す」しか手段がない。

- **価格記録**: API は追加（`POST /api/products/:id/price-records`）と削除
  （`DELETE /api/products/:id/price-records/:priceRecordId`、
  `apps/web/src/server/routes/products.ts:70-78`）のみ。編集 API・編集 UI ともに無い。
- **店舗名**: `apps/web/src/server/routes/stores.ts` に一覧・作成・使用件数取得・削除はあるが
  更新（`PUT`）ハンドラが無い。`Store`（`packages/domain/src/shared/store.ts`）は
  `storeName` を含む全フィールドが `private readonly` で、リネームに使えるメソッドが存在しない。

店舗のリネームは 2026-07-27 に一度 ADR-0013 案C として検討され、**却下されている**
（`docs/decisions/ADR-0013-store-limit-and-delete-cascade.md` §Alternatives 案C）。ただし
その却下理由は「重複店舗を 1 つに統合したいなら、リネームではなくマージ（価格記録の
`storeId` を付け替えて片方を消す）が必要」という**重複統合の文脈に限定**されている。
今回の要求は「打ち間違えた 1 件の店舗名を訂正する」ことであり、重複統合とは別の目的である。
この整理は ADR-0015 として別途起票する（本要件・設計書では新方針の実装内容を確定し、
却下理由の射程についての論点整理のみ設計書に残す）。

## 目的

打ち間違えた価格記録（店舗・価格・内容量）と店舗名を、削除して記録し直すことなく
画面から直接修正できるようにする。Sprint 7 の残り完了条件を満たす。

## ユーザー要求（原文の要約）

- 商品詳細の「最近の記録」に出ている価格記録を、値を直接編集して直したい
  （店舗を間違えた・価格を打ち間違えた・内容量を間違えたケース）。
- 店舗名を打ち間違えたとき、削除して価格記録ごと失わずに名前だけ直したい。

## 機能要件

| ID  | 内容                                                                                                                                     |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| F-1 | 商品詳細画面の「最近の記録」（直近 5 件）から、価格記録 1 件を選んで店舗・価格・内容量を編集できる |
| F-2 | 価格記録の編集では単価（`unitPrice`）を `UnitPriceCalculator` で再計算する                                                               |
| F-3 | 価格記録の編集では記録日時（`observedAt`）と ID は元の値を維持し、変更できない                                                          |
| F-4 | 店舗の名前を編集（リネーム）できる                                                                                                        |
| F-5 | 店舗のリネームには既存の同名禁止ルール（`normalizeStoreName` + `findByNormalizedName`、ADR-0013）を適用する。ただし対象店舗自身との比較では衝突と判定しない |
| F-6 | 店舗をリネームすると、その店舗を参照する価格記録・買い物品目の表示名も自動的に新しい名前になる（`storeId` 参照のため、データの付け替えは不要） |

## 非機能要件（性能・セキュリティ・可用性など。無ければ「対象外」）

対象外。外部 I/O の新設、大量データを扱うクエリの新設・変更、明示された性能要件のいずれにも
該当しない（既存の `save()` upsert 経路をそのまま使う。設計書 §性能 参照）。

## 正常系

| ID   | シナリオ                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------------- |
| N-01 | 「最近の記録」の 1 件を編集し、店舗のみ変更して保存すると、その記録の店舗表示が変わり単価は再計算される       |
| N-02 | 「最近の記録」の 1 件を編集し、価格のみ変更して保存すると、価格と単価が更新される                              |
| N-03 | 「最近の記録」の 1 件を編集し、内容量のみ変更して保存すると、内容量と単価が更新される                          |
| N-04 | 編集後も記録日時（`observedAt`）は変更前と同じ値のまま表示される（価格推移グラフの位置が動かない）              |
| N-05 | 編集後、最安店舗表示・価格推移グラフ・買い物リストの単価比較（`price-comparison.ts`）が新しい値で再計算される |
| N-06 | 店舗名を編集して保存すると、一覧・プルダウン・価格記録の店舗表示すべてが新しい名前になる                       |
| N-07 | 店舗名を同じ値（大文字小文字だけ変える等、正規化後に異なる名前）に変更でき、同名エラーにならない               |
| N-08 | 店舗名を編集せず同じ文字列のまま保存しても、自分自身との重複として拒否されない（冪等に成功する）               |

## 異常系

| ID   | シナリオ                                                                             | 期待される挙動                            |
| ---- | -------------------------------------------------------------------------------------- | ------------------------------------------- |
| E-01 | 存在しない商品 ID に対して価格記録の編集を送信する                                     | 404（`ProductNotFoundError`）              |
| E-02 | 存在する商品だが、存在しない・すでに削除済みの価格記録 ID を編集しようとする           | 404（`PriceRecordNotFoundError`）          |
| E-03 | 価格記録の編集で、存在しない店舗 ID を指定する（同時に店舗が削除された等）             | 404（`StoreNotFoundError`）                |
| E-04 | 価格記録の編集で、価格が 0 以下・内容量が 0 以下を送信する                             | 400（Zod バリデーション）                  |
| E-05 | 存在しない店舗 ID に対して店舗名の編集を送信する                                       | 404（`StoreNotFoundError`）                |
| E-06 | 店舗名の編集で、正規化後の名前が自分以外の既存店舗と一致する                           | 422（`DuplicateStoreNameError`）           |
| E-07 | 店舗名の編集で、空文字列・空白のみ・256 文字以上を送信する                             | 400（Zod バリデーション）                  |
| E-08 | 価格記録の編集リクエストが通信エラー・タイムアウトで失敗する                           | 画面にエラーメッセージを表示し、値は失われない（フォームを保持） |
| E-09 | 店舗名の編集リクエストが通信エラーで失敗する                                            | 画面にエラーメッセージを表示し、値は失われない |
| E-10 | 「最近の記録」に出ていない 6 件目以降の価格記録を編集しようとする                       | UI 上、編集の導線自体が無い（対象外。境界条件 B-05 参照） |

## 境界条件（null・空・上限/下限・権限境界）

| ID   | 内容                                                                                                       |
| ---- | -------------------------------------------------------------------------------------------------------------- |
| B-01 | 価格：1 円以上の整数（既存の新規記録フォームと同じ下限）                                                       |
| B-02 | 内容量：0 より大きい数値（`Quantity` の制約を踏襲。`PriceRecord.create()` の正数バリデーションを再利用）        |
| B-03 | 店舗名：空白のみは不可、255 文字以内（`createStoreSchema` の `nonBlankString` と同じ制約）                     |
| B-04 | 店舗名の同名判定：`normalizeStoreName()`（trim + NFKC）後の完全一致。大文字小文字は区別する（ADR-0013 を踏襲） |
| B-05 | 編集対象は商品詳細「最近の記録」に表示される直近 5 件のみ。6 件目以降は編集できない（D-2 確定・表示件数拡張は対象外） |
| B-06 | 価格記録の編集で `observedAt`・`id` は不変（D-1 確定・編集フォームに記録日時の入力欄を出さない）               |
| B-07 | 店舗のリネームは、店舗マスタ上限 3 件・登録件数には影響しない（既存店舗の名前を変えるだけで件数は増減しない）    |
| B-08 | 店舗リネーム時、`GetStoreUsageUseCase` で得られる参照件数（価格記録・買い物品目）が 0 件でも編集は成功する（警告表示の有無に関わらず操作は妨げない） |

## 前提

- 認証機能は無い（ADR-0003）。操作主体の区別・権限制御は行わない。
- 価格記録の `id`・店舗の `id` は UUID で、集約内で一意。
- `DrizzleProductRepository.save()` は `priceRecords` を全列 `onConflictDoUpdate` で upsert しており、
  `DrizzleStoreRepository.save()` は `name` を `onConflictDoUpdate` で upsert している
  （`packages/infrastructure/src/repositories/drizzle-product.repository.ts:98-116`、
  `packages/infrastructure/src/repositories/drizzle-store.repository.ts:33-44`）。
  既存の ID を維持したまま値を差し替えて `save()` を呼べば、Infrastructure 層・DB スキーマの
  変更なしに更新が成立する。
- 店舗削除はカスケードで価格記録も物理削除するため（ADR-0013）、現存する価格記録の `storeId` は
  常に存在する店舗を指す。編集ダイアログが参照する店舗一覧に「存在しない店舗」は混在しない。

## 制約

- `.claude/rules/domain-layer.md` / `coding-standards.md` / `presentation-layer.md` を厳守する。
- Domain 層の変更は `static create()` / `static reconstruct()` パターンと不変条件維持の原則に従う。
- 価格記録の不変性（`PriceRecord` の全フィールド `readonly`）は維持する。`PriceRecord.update()` は
  作らない（D-3 確定・却下済み）。編集は「新しい `PriceRecord` を生成して配列内を置換する」
  差し替え方式で行う（`Product.updatePriceRecord()`）。
- API 契約（Zod スキーマ）の最終形は本書では確定しない。エンドポイントと項目の方針までとし、
  詳細は contract-designer に委ねる。
- 実装コードは本書・設計書のいずれでも変更しない。

## 対象範囲

- `packages/domain`: `Product.updatePriceRecord()` の追加、`Store.rename()` の追加。
- `packages/application`: `UpdatePriceRecordUseCase`、`RenameStoreUseCase` の新設と関連 DTO・マッパー拡張。
- `packages/api-contract`: 価格記録更新・店舗リネームのリクエストスキーマ（方針のみ。最終形は契約設計で確定）。
- `apps/web`（Presentation 層）: `PUT /api/products/:id/price-records/:priceRecordId`、
  `PUT /api/stores/:id` の Hono ルート追加。商品詳細画面の「最近の記録」に編集導線を追加。
  店舗管理カード（`PriceRecordForm` 内）にリネーム導線を追加。

## 対象外

- 記録日時（`observedAt`）の編集。
- 商品詳細「最近の記録」の表示件数拡張（6 件目以降の編集）。
- 店舗の統合（マージ）機能。重複店舗の解消はリネームでは行えない（ADR-0013 案C の却下理由どおり）。
- 店舗マスタの上限件数（3 件）の変更。
- 価格記録・店舗名の変更履歴（監査ログ）の保存。編集は上書きであり、編集前の値は復元できない
  （既存の削除と同じ「取り消し（undo）は無い」方針を踏襲）。
- 独立した店舗一覧・店舗管理専用画面の新設（既存どおり商品詳細内の店舗カードに留める）。
- 価格記録の一括編集・複数件同時操作。
- DB スキーマ変更・マイグレーション（Infrastructure 層は upsert 済みのため不要）。
- 認証・権限制御の追加。

## 後方互換性・データ移行（該当なければ「対象外」）

対象外。DB スキーマ変更が無いため、既存データへの移行は不要。既存の API
（`POST /price-records`・`DELETE /price-records/:id`・`POST /stores`・`DELETE /stores/:id`）は
そのまま残り、破壊的変更を行わない。新設する `PUT` エンドポイントは既存の挙動と共存する。

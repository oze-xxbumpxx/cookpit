# 要件定義: store-delete-and-unit-price-basis

- ステータス: confirmed
- レベル: L3
- 関連: `docs/designs/store-delete-and-unit-price-basis.md` /
  `docs/decisions/ADR-0012-store-delete-restrict-on-reference.md` /
  `docs/designs/store-master.md` / `docs/designs/product-master.md` /
  ADR-0011（物理削除の先例）/ ADR-0008（単位の自由記述）

## 背景

実運用（2026-07-27・パートナーからの指摘含む）で 3 つの不都合が出た。

1. **単価が常に「100g あたり」で出る。** 砂糖は 1kg 袋で買うので、`298円 / 100g` ではなく
   `298円 / 1kg` の方が買い物中の感覚と合う。`UnitPriceCalculator` が重量を 100g 基準・
   容量を 100ml 基準へ正規化して保存し、`unitPriceBasisLabel` が `g`/`kg` を一律 `'100g'` と
   表示していることが原因。
2. **誤入力した価格記録を直せない。** 内容量欄（`QuantityField`）は「数値+単位」の自由入力で、
   `3001kg`（= 値 3001 / 単位 kg）という記録が本番データに残っている。
   `parseQuantity('3001kg')` は仕様どおり値 3001・単位 kg を返しており**コードのバグではない**。
   価格記録を消す手段も直す手段も UI・API のどちらにも無いため、ユーザーが自力で復旧できない。
3. **不要な店舗を消せない。** 店舗の登録（`POST /api/stores`）はあるが削除が無く、
   試し入力で作った店舗がプルダウンに残り続ける。

## 目的

- 単価表示を、記録したときの内容量の単位に沿った基準で読めるようにする。
- 誤って記録した価格記録を、ユーザーが画面から取り除けるようにする。
- 不要な店舗を、ユーザーが画面から削除できるようにする。ただし**参照が残っている店舗を
  消して価格履歴を失う事故は起こさない**。

## ユーザー要求（原文の要約）

- 「砂糖一キロ単位でいいのに 100g あたりのが出ててちょっと違和感」
- 「内容量の 3001kg も 1kg に直るなら直してほしい」
- 「店舗のプルダウンに変なのがいるから消してほしい」「店舗のプルダウンに店舗削除を行えるようにしたい」

確認済みの選択（2026-07-27）:

| 論点             | 選択                                                             |
| ---------------- | ---------------------------------------------------------------- |
| 単価の表示基準   | **入力した内容量の単位に合わせる**（1kg 入力 → 円/kg）           |
| 誤入力の修正手段 | **価格記録の削除を追加**（編集は今回作らない）                   |
| 店舗削除の挙動   | **参照があれば削除させない**（論理削除もカスケード削除もしない） |

## 機能要件

| ID  | 要件                                                                                                           |
| --- | -------------------------------------------------------------------------------------------------------------- |
| F-1 | 単価の表示基準を内容量の単位から決める。`kg` → 1kg、`g` → 100g、`l` → 1L、`ml` → 100ml、それ以外 → `1<単位>`   |
| F-2 | 単価の**保存値**（`price_records.unit_price_amount`）は現行どおり 100g / 100ml 基準の正準値のまま変えない      |
| F-3 | 商品詳細の「最近の記録」から価格記録を 1 件ずつ削除できる                                                      |
| F-4 | 価格記録の削除前に確認ダイアログを出す                                                                         |
| F-5 | 店舗一覧から店舗を 1 件ずつ削除できる。削除前に確認ダイアログを出す                                            |
| F-6 | 店舗が価格記録または買い物リストの品目から参照されている場合、削除を拒否し、参照件数を含むメッセージを表示する |
| F-7 | 削除した店舗が価格記録フォームで選択中だった場合、選択を解除する                                               |
| F-8 | 削除はサーバーに永続化される。再読み込み後も消えたままである                                                   |

## 非機能要件（性能・セキュリティ・可用性など）

- 性能: 参照件数の確認は `COUNT(*)` 2 本（価格記録 / 買い物品目）。2 人利用・数百行規模のため
  追加インデックスは不要（`price_records` は `store_id` に索引が無いが、全件数が小さいので
  シーケンシャルスキャンで足りる）。
- セキュリティ: MVP1 は認証なし（ADR-0003）。認可の観点は対象外。パスパラメータは
  `zValidator` で UUID 形式を検証する。
- 可用性: 追加の外部依存なし。

| ID  | シナリオ                                                                   |
| --- | -------------------------------------------------------------------------- |
| N-1 | 1kg で記録した砂糖の詳細画面で、単価が `〇〇円 / 1kg` と表示される         |
| N-2 | 300g で記録した商品は従来どおり `〇〇円 / 100g` と表示される               |
| N-3 | `3001kg` の価格記録を削除すると、一覧・最新価格・最安店舗の表示から消える  |
| N-4 | 削除後に `1kg` で記録し直すと、`298円 / 1kg` として表示される              |
| N-5 | どこからも参照されていない店舗を削除すると、プルダウンと店舗一覧から消える |
| N-6 | 参照のある店舗の削除を試すと拒否され、店舗は残る                           |

| ID  | シナリオ                           | 期待                               |
| --- | ---------------------------------- | ---------------------------------- |

| E-2 | 存在しない価格記録 ID を削除       | 404                                |
| E-3 | 存在しない店舗 ID を削除           | 404                                |

## 境界条件（null・空・上限/下限・権限境界）

| ID  | 条件                                                          | 期待                                                              |
| --- | ------------------------------------------------------------- | ----------------------------------------------------------------- |
| B-1 | 価格記録が 1 件だけの商品でその 1 件を削除                    | 価格履歴 0 件。「価格未登録」表示に戻り、最安店舗も「未登録」     |
| B-2 | 店舗が 1 件だけで、それを削除（参照なし）                     | 店舗 0 件。価格記録フォームは「店舗がまだ登録されていません」表示 |
| B-3 | 単位が `g`/`kg`/`ml`/`l` 以外（`個`・`袋` など自由記述）      | `1個` のように単位そのものを基準に表示（現行と同じ）              |
| B-4 | 単位が `KG` のような大文字・表記ゆれ                          | 正準化側（`UnitPriceCalculator`）と同じ厳密一致で「その他」扱い   |
| B-5 | 買い物品目の `targetStoreId` のみが参照している店舗（購入前） | 参照ありとして削除を拒否                                          |

## 前提

- `DrizzleProductRepository.save()` は集約に残っていない価格記録行を `notInArray` で DELETE する
  （既存の PGlite テストで保証済み）。集約から取り除くだけで永続化まで追随する。
- ID はすべて `randomUUID()` 由来のため、`z.uuid()` で検証できる。
- `apps/web/src/server/app.ts` の `onError` が `NotFoundError` → 404、
  `InvalidOperationError` → 422 に変換する。新しいエラークラスは基底を継承させるだけでよい。

## 制約

- 本番 DB（Neon）の中身を開発側から直接書き換えない。**誤データの復旧は UI 経由で行う。**
- `packages/domain` は他パッケージに依存しない（Clean Architecture）。
- DB スキーマ変更・マイグレーションは行わない。

## 対象範囲

Domain / Application / Infrastructure / Presentation（Hono ルート + 画面）の 4 層。
api-contract は既存 `idParamSchema` の再利用と、価格記録 ID 用パラメータの追加のみ。

## 対象外

- 価格記録の**編集**（削除して記録し直す運用で足りるとユーザーが選択）
- 店舗の**リネーム**
- 店舗の論理削除（アーカイブ）
- カスケード削除（参照ごと消す案は不採用。ADR-0012 §Alternatives）
- 単価の**保存値**の基準変更・既存データの再計算
- 商品ごとの表示単位設定（案として提示したが不採用）
- 買い物リスト画面・在庫画面の店舗プルダウンへの管理 UI 追加（店舗の追加 UI が
  価格記録フォームにしか無いため、削除も同じ場所に集約する）
- DB マイグレーション

## 後方互換性・データ移行

- **既存データの移行は不要。** 単価の保存値も単位の保存値も変えない。表示だけ変わる。
- API は追加のみ。既存エンドポイントのリクエスト・レスポンス形は変えない。
- `PriceRecordDto` に `id` フィールドを**追加**する（破壊的変更ではない）。

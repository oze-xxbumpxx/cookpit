# ADR-001: Web アプリで実装する

**ステータス**: 採択
**決定日**: 2026-05

## 背景

「彼女と日常的に使えるアプリ」というユースケースに対し、以下の選択肢があった。

- A. ネイティブアプリ（React Native + Expo）
- B. Web アプリ（Next.js）
- C. PWA（Web アプリのネイティブ風体験）

## 検討した観点

| 観点                 | ネイティブ | Web                 | PWA         |
| -------------------- | ---------- | ------------------- | ----------- |
| 起動の気軽さ         | ◎          | △                   | ○           |
| プッシュ通知         | ◎          | ×                   | △ (iOS制限) |
| カメラ               | ◎          | △                   | △           |
| オフライン買い物     | ◎          | ×                   | ○           |
| 開発の手間           | やや重い   | 軽い                | 軽い        |
| 配布の手軽さ         | ストア経由 | URL共有             | URL共有     |
| 開発者の現職スキル   | 中         | 高（Webエンジニア） | 高          |
| 業務スタックとの近さ | 中         | 高                  | 高          |

## 決定

**Web アプリ（Next.js）を採用する。** さらに **PWA 化**することで、ネイティブ風の体験（ホーム画面追加・オフライン対応）を提供する。

## 決定の理由

1. **開発者の現職が Web エンジニア**であり、業務スキルがそのまま活きる
2. ネイティブアプリの開発（iOS ビルド、ストア審査）は学びにはなるが、2〜3ヶ月の開発期間における**手数を増やす**ことになり、本質機能の作り込みに時間を割けなくなる
3. PWA 化により、起動の気軽さ・オフライン対応の課題はおおむね解決できる
4. プッシュ通知は MVP1 のスコープ外なので、ネイティブのアドバンテージが活きる場面が少ない
5. 配布が URL 共有で済むため、2人で使い始めるハードルが極めて低い

## 帰結

### ポジティブ

- 開発スピードが最大化される
- 業務スキルの延長で進められる
- iPhone と Android の両方で同じコードベースで動く

### ネガティブ

- iOS の PWA 制約（ローカルストレージが7日でクリアされる場合あり、プッシュ通知の制限）に注意が必要
- カメラを使った OCR 等を Phase 2 で導入する場合、ネイティブほどの体験は得られない可能性がある

## フォローアップ

- iOS の PWA 制約は「サーバーが真実のソース、ローカルはキャッシュ」設計で回避する
- 将来、ネイティブが必要になった場合は Capacitor で Next.js をネイティブ化する選択肢が残る

# 01. プロジェクト概要

## プロジェクトの目的

毎週の作り置き運用を支える、2人で使う献立・買い物・在庫管理アプリ。

紙のレシピブックの限界、複数店舗の価格比較の手間、在庫の見える化という日常の困りごとを、技術スタックの挑戦と両立させて解決する個人開発プロジェクト。

## 対象ユーザー

アプリの利用者は開発者本人とパートナーの 2 名のみ。不特定多数への提供は想定しない。

ただし**ソースコードは GitHub で公開している**。「リポジトリを公開すること」と「アプリを
一般に開放すること」は別であり、本番デプロイは Basic 認証で保護して利用者を 2 名に限定した
まま運用する。経緯は
[ADR-0021](./decisions/ADR-0021-basic-auth-for-public-repository.md) を参照。

## 解決したい課題

実際のヒアリングから抽出した、現状の困りごと。

### 1. 価格比較の手間

複数店舗で安い商品を探したいが、店舗ごとの価格を覚えておくのが大変。今週どの店舗で何を買うのが最適かを判断したい。

### 2. 在庫の見える化

家に何があり、何が足りないかが買い物中にわからない。買い物中の同期で「今買って良いもの・追加で必要なもの」が分かると便利。

### 3. 在庫管理ができていない

そもそも在庫を管理する仕組みがなく、買いすぎ・買い忘れが起きる。

### 4. レシピブックの紙ベース運用

レシピを紙でまとめているが、すぐに参照できない。デジタル化したい。

## ユーザーの実運用

設計の前提となる、現在の運用フロー。

### 土曜日のフロー

1. 2人で相談して今週の献立を決める（提案があると嬉しい）
2. 買い物リストを作る
3. 2人で2店舗を回って買い物
4. 帰宅後、平日5日分の夕食を作り置き

### 平日の消費

作り置きしたものを、組み合わせを変えながら**ビュッフェ方式**で消費する。日付とレシピが1対1で固定されない運用。

## スコープ

### MVP1 のスコープ

| 機能                                  | 優先度                                       |
| ------------------------------------- | -------------------------------------------- |
| レシピ CRUD                           | 高（紙のレシピをデジタル化）                 |
| 商品マスタ・価格履歴                  | 高（価格比較の基盤）                         |
| 週次献立作成                          | 高（ビュッフェ方式に対応）                   |
| 買い物リスト（自動生成 + チェック）   | 高（土曜運用の中核）                         |
| 価格比較ビュー                        | 高（困りごとへの直接対応）                   |
| 在庫管理（買い物自動追加・手動消費）  | 高（在庫見える化）                           |
| PWA（ホーム画面追加・オフライン対応） | 中（日常に溶け込ませる）                     |
| 単位プルダウン選択（プリセット固定）  | 中（材料入力 UX 改善・パートナーからの要望） |

### MVP1 のスコープ外（Phase 2 以降）

- 認証・複数ユーザー対応
- 賞味期限アラート
- レシピ提案（LLM活用）
- 履歴・分析ビュー
- 食材ロス分析
- レシピのOCR取り込み
- プッシュ通知

## 制約

### 技術制約

- **継続費用なし**：個人開発のため AWS など継続課金が発生するインフラは使わない
- **無料枠で完結**：Vercel + Neon の無料枠で運用
- **クロスプラットフォーム**：iPhone（開発者）と Android（パートナー）の両方で動作する必要がある

### 期間制約

- 開発期間 2〜3 ヶ月
- 2週間スプリント
- Sprint 1 完了時点（レシピ CRUD ができた段階）から実利用を開始

### 開発リソース制約

- 開発者は1名（業務時間外で開発）
- 学習機会としても価値のある技術選定をしたい

## プロジェクトの位置づけ

本プロジェクトは、以下の3つの目的を兼ねる。

1. **日常の課題解決**：上記の困りごとを実際に解決する
2. **技術スキルの拡張**：業務スタック（TypeScript / GraphQL / Clean Architecture / DDD）を活かしつつ、新技術（Next.js 16、Hono、Drizzle、Neon、Better Auth、Serwist）を獲得する
3. **設計の素振り**：Clean Architecture + DDD を個人開発のスケールで実践する

# 試験計画: recipe-edit-screen

- 前提となる設計書: docs/designs/recipe-edit-screen.md
- レベル: L2
- 作成日: 2026-06-25

## 試験種別

本機能は Presentation 層のみの増分（バックエンド変更なし）であるため、試験は以下の範囲を対象とする。

- **手動統合試験（主）**: ブラウザ上でユーザー操作を行い、画面・API・DB 永続化まで一気通貫で確認する。MVP1 の現時点では Presentation 層の自動テストランナーは未導入のため、観点は手動試験として設計する（自動化対応時にそのまま利用できる粒度を維持する）。
- **Domain 層単体テスト（対象外）**: 本件は Presentation 層増分であり Domain / Application / Infrastructure 層への変更がない。既存の Domain 層テスト（`packages/domain/src/**/*.test.ts`）への影響はなく、追加・変更は不要。
- **結合（API 単体）**: `PUT /api/recipes/:id` は既存実装済みのため、API 層の試験は本計画の対象外（回帰として既存テストで担保する前提）。

`create-test-plan` Skill の「観点の選択基準」表を以下のとおり適用する。

| ------------------------------------------------------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 特性観点

### 権限

MVP1 は認証なし（ADR-003 準拠）。URL を知っていれば誰でも編集可能。これは既存の削除機能と同一の前提であり、本機能追加で状況は変わらない。権限に関する試験観点は Phase 2 認証導入時に追加する。

### データ整合性

| #   | 観点                                                | 前提                                     | 操作                           | 期待結果                                                                                                 | 分類   |
| --- | --------------------------------------------------- | ---------------------------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------- | ------ |
| D1  | 保存後に詳細画面が最新値を表示する                  | 保存成功直後                             | 詳細画面を確認する             | DB に保存された値と詳細画面の表示値が一致する（`router.refresh()` により Server Component が再フェッチ） | 整合性 |
| D2  | baseServings が保存後も変化しない                   | 編集前に `baseServings=4` のレシピ       | 任意のフィールドを変更して保存 | 保存後の詳細画面でも `baseServings` は 4 のまま（送信していないため変化しない）                          | 整合性 |
| D3  | amountNote 系 ingredient が保存後も正しく表示される | '少々' 等の amountNote を持つ ingredient | 保存                           | 詳細画面で amountNote 値（'少々'）が正しく表示される                                                     | 整合性 |

### 冪等性

対象外。設計上「楽観的更新は採用しない。保存後 redirect を採用する」のため、フロントエンドからの PUT 再送・リトライは発生しない。UI が `submitting` フラグで二重送信を防止する（観点 U20 で検証）。API レベルの冪等性は Application/Infrastructure 層の関心事であり、本計画のスコープ外。

### 障害系（外部 I/O）

対象外。本機能は既存の PUT エンドポイントを呼ぶだけで、新規の外部 I/O（DB 以外の外部 API/ストレージ）を持たない。ネットワーク障害によるエラーメッセージ表示は FE 固有観点（観点 I15）で扱う。

### フロントエンド固有（必須）

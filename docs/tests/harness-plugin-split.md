## 結合試験観点

| #   | 観点   | 前提 | 操作 | 期待結果 | 分類 |

| —   | 対象外 | —    | —    | —        | —    |

対象外の理由: 本 Phase では Plugin を実際に install できない（リポジトリ作成は Phase 3）。
「core だけ install した環境で動く」ことの実証は **Phase 3 の結合試験**に持ち越す。
本 Phase は静的な依存関係の担保までを範囲とする（設計書「移行とリリース」）。

これは既知の限界であり、隠さず Phase 3 の受け入れ条件へ引き継ぐ。

## 特性観点

- **権限**: 対象外。ファイルの所属を変えるだけで権限モデルに変更なし。
- **データ整合性**: メトリクス YAML の形式不変（観点 7 で実行確認）。状態ファイルは無変更。
- **冪等性**: `record-task-metrics.sh` の冪等性（2 回目以降は `machine:` のみ再集計）は
  改名で壊れていないこと。観点 7 の実行で確認する。
- **障害系（外部 I/O がある場合）**: 対象外。外部 API / ストレージへの I/O なし。
- **フロントエンド**: 対象外（`apps/web` 変更なし）。
- **防御性（Domain 層 Entity/VO の場合）**: 対象外（`packages/domain` 変更なし）。
- **縮退時の挙動**（本 Phase 固有）: improvement 層が無い環境で `close-session` が
  失敗せずスキップすること。**静的レビューで確認**（実環境での検証は Phase 3）。

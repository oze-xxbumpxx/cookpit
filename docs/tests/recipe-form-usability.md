# 試験計画: recipe-form-usability

- 前提となる設計書: `docs/designs/recipe-form-usability.md`
- レベル: L2

## 試験種別

| 対象                                                 | 種別                     | ランナー                                |
| ---------------------------------------------------- | ------------------------ | --------------------------------------- |
| 純関数（`moveArrayItem` / `isRecipeFormDirty`）      | 単体                     | Vitest node project（`*.node.test.ts`） |
| フック（`useLeaveConfirmation`）                     | 単体（ハーネス + RTL）   | Vitest dom project（`*.test.tsx`）      |
| 画面（`RecipeFormFields` / `RecipeFormClient`）      | 単体（RTL + user-event） | Vitest dom project                      |
| ドラッグのタッチ挙動・スクロール競合・スワイプバック | **実画面確認**           | PGlite dev + Playwright                 |

E2E（Playwright spec）は既存の `recipe-crud.smoke.spec.ts` のみで、本件は**対象外**
（実画面確認で代替する）。

### happy-dom の制約（重要）

- `getBoundingClientRect()` が常に 0 を返すため、dnd-kit は要素位置を測れず並べ替え先を
  決定できない。テストでは兄弟内の位置から縦に積んだ矩形を返すスタブ（`stubVerticalRects`）を
  入れて計測だけを成立させる。
- dnd-kit の `KeyboardSensor` は `event.key` ではなく **`event.code`** を見る。user-event では
  **物理キーコード記法（角括弧 `[Space]` / `[ArrowDown]`）**で送る必要がある。
- RTL は React ルートをコンテナ div に作るが、**Next.js App Router は `document` をルートに
  してハイドレートする**。この差のためリスナ登録先（window / document）の優先順位は
  自動テストで再現できない。→ 実画面確認 E-5 で担保する。

## 特性観点

- **権限 / データ整合性 / 冪等性 / 障害系**: 外部 I/O も状態遷移も伴わない UI 変更のため**対象外**。
- **フロントエンド固有**: ローディング（既存の「保存中」表示。変更なし）／エラー表示（既存の
  バナー。保存失敗時にガードが解除されないことを確認）／楽観的更新（**対象外** — 本件では
  使わない）。
- **防御性（Entity/VO）**: Domain 層の変更が無いため**対象外**。純関数の非破壊性は MAI-07 で確認。
- **アクセシビリティ**: ハンドルの `aria-label`、キーボード操作（RFF-10/11）、
  読み上げ通知の日本語化（`accessibility.announcements`）。

### 実画面確認で見つかった不具合（自動テストでは検出できなかった）

1. **capture リスナの登録先が `document` では遅い。** Next.js App Router は `document` を
   React のルートコンテナにしてハイドレートするため、React の capture リスナも `document` に
   付く。同一ノードのリスナは登録順に走り、ハイドレートは `useEffect` より先に終わっているので、
   `document` に登録すると Link の `onClick` が先に走って遷移してしまう。**`window`** に
   登録して先取りする形へ修正した。RTL はルートをコンテナ div に作るため、この差は
   自動テストで再現できない。
2. **リンク内の SVG アイコンをクリックすると素通りしていた。** ボトムナビのタブはアイコンを
   含むためクリック対象が `SVGElement` になり、`target instanceof HTMLElement` の判定で
   早期 return していた。`Element` へ広げて修正し、回帰テスト LG-15 / LG-16 を追加した
   （旧実装で FAIL することを確認済み）。
3. **dnd-kit のハイドレーション不一致。** `DndContext` に `id` を渡さないと
   `aria-describedby` をインスタンス連番で採番するため、SSR と CSR で値がずれる。
   `useId()` を `id` に渡して解消した。

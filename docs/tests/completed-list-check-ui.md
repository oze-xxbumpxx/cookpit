# 試験計画: completed-list-check-ui

- 対応設計書: docs/designs/completed-list-check-ui.md（L2）
- 対応実装計画: docs/implementation-plans/completed-list-check-ui.md

## 基本方針

本件は「サーバーの制約と UI の食い違い」であり、**サーバー側の挙動は正しく、変えない**。
したがって検証の主眼は Presentation 層に置く。

再現手順（実施済み）で分かったとおり、完了済みリストでは check / uncheck だけでなく
`markAsBought` / `reassignStore` も 422 になる。行内 3 つの操作要素を**個別に**固定する。

なお本件は「非同期 UI 状態の遷移が試験計画から漏れる」（`candidates/project-refactoring.md`
事象 1）と同じ系統の見落とし — 実際にはサーバーが拒否する状態を UI が許していた — であり、
その意味でも操作可否をテストで固定する価値が高い。

## A. 完了済みリストでの操作可否（新規・本件の中核）

| ID  | 観点                                                 | 期待                                                           |
| --- | ---------------------------------------------------- | -------------------------------------------------------------- |
| A-1 | 完了済みリストのチェックボックス                     | `disabled`。`aria-checked` は現状の値を保つ                    |
| A-2 | 完了済みリストの「金額を記録」ボタン                 | 描画されない                                                   |
| A-3 | 完了済みリストの店舗チップ                           | `disabled`                                                     |
| A-4 | 完了済みリストでも品目名・数量・記録済み価格は読める | 表示される                                                     |
| A-5 | 完了済みリストに回復導線が出る                       | 「買い物を再開」ボタンと、変更するには再開が必要である旨の文言 |
| A-6 | active なリストでは従来どおり操作できる              | チェックボックス・店舗チップとも操作可、「金額を記録」も表示   |
| A-7 | 「買い物を再開」後は再び操作できる                   | reopen 成功後にチェックボックスが有効化される                  |

## B. 422 の文言（2 人利用の競合）

`readOnly` により UI からは操作できなくなるが、相手が先に完了した直後は自分の画面が
まだ `active` のままで操作でき 422 が返り得る。

| ID  | 観点                            | 期待                                                             |
| --- | ------------------------------- | ---------------------------------------------------------------- |
| B-1 | チェック操作が 422 を返したとき | 「買い物完了後は変更できません。「買い物を再開」してください。」 |
| B-2 | 店舗再割当が 422 を返したとき   | 同上                                                             |
| B-3 | 422 以外の失敗（500 など）      | 従来どおり「操作に失敗しました。」                               |
| B-4 | 通信エラー（例外）              | 従来どおり「通信エラーが発生しました。」                         |

## E. 実画面確認（dev:pglite + Playwright）

| ID  | 観点                                       | 期待                                 |
| --- | ------------------------------------------ | ------------------------------------ |
| E-1 | 完了済みリストでチェックボックスをクリック | 反応せず、エラーバナーも出ない       |
| E-2 | active なリストでチェック → 解除           | 双方とも成功し、エラーバナーが出ない |
| E-3 | 「買い物を再開」→ チェック解除             | 成功する                             |

修正前の実画面では E-1 が「押せてしまい『操作に失敗しました。』が出る」状態だった
（スクリーンショットで記録済み）。

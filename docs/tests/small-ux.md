# 試験計画: small-ux

- 前提となる設計書: `docs/designs/small-ux.md`
- レベル: L2

## 試験種別

| 対象                                                             | 種別                     | ランナー                        |
| ---------------------------------------------------------------- | ------------------------ | ------------------------------- |
| 純関数（`isProductFormDirty` / 手順並べ替えが dirty になること） | 単体                     | Vitest node（`*.node.test.ts`） |
| 商品フォーム画面（new / edit）                                   | 単体（RTL + user-event） | Vitest dom（`*.test.tsx`）      |
| `RecipeFormFields` の手順並べ替え                                | 単体（RTL + user-event） | Vitest dom                      |
| タッチのスクロール競合・商品画面のスワイプバック                 | **実画面確認**           | PGlite dev + ブラウザ           |

E2E（Playwright spec）は本タスクでは**対象外**（実画面確認で代替する）。

### 観点の取捨

- **冪等性 / 障害系 / 防御性（Entity/VO）**: 対象外（外部 I/O も Domain 変更も無い UI）。
- **フロントエンド固有**: 必須。ローディング（既存の「保存中」。変更なし）／エラー表示（保存失敗時にガードが解除されない）／楽観的更新（使わないので対象外）。
- `useLeaveConfirmation` の LG-* は既存テストで固定済み。本件では再実装しない。

### happy-dom の制約

材料並べ替えと同じ。

- `getBoundingClientRect()` が常に 0 のため、兄弟位置から縦矩形を返すスタブを入れる。
- dnd-kit の `KeyboardSensor` は `event.code` を見る。user-event では `[Space]` / `[ArrowDown]` を使う。

## 結合試験観点

本タスクは API・DB を変えない。Hono ルート結合は**対象外**。

## 特性観点

- 権限: 対象外
- データ整合性: 対象外（サーバー状態を変えない）
- 冪等性: 対象外
- 障害系: 対象外
- フロントエンド: PFC-06（保存失敗後も入力が残りガードが働く）
- 防御性: 対象外（Domain 変更なし）
- 集合の過不足: 別名の正規化結果は配列の `toEqual` で固定する（PFD-04 / PFD-06）

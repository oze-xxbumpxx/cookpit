# 試験計画: project-refactoring

- 対応設計書: docs/designs/project-refactoring.md（L2）

## 基本方針

挙動不変のリファクタリングであるため、**新規テストは原則追加しない**。既存テストスイートが
そのまま回帰検知装置になる。テストを追加・変更した場合は「なぜ必要だったか」を最終報告に残す。

判定は「ベースラインとの一致」で行う。ベースラインは実装着手前に実測した以下の値。

| ゲート         | ベースライン（2026-07-25 実測）                                                      |
| -------------- | ------------------------------------------------------------------------------------ |
| type-check     | 5/5 PASS                                                                             |
| lint           | 0 error / 1 warning（既存: `product-form-fields.test.tsx` の未使用変数。スコープ外） |
| domain         | 352 PASS                                                                             |
| application    | 205 PASS                                                                             |
| infrastructure | 53 PASS                                                                              |
| api-contract   | 220 PASS                                                                             |
| web            | 439 PASS                                                                             |
| 合計           | 1269 PASS                                                                            |

## 対象外

- E2E（Playwright）の追加。既存の `recipe-crud.smoke.spec.ts` に変更は不要。
- 実画面確認（manual-browser-verify）。挙動不変のため必須ではないが、
  観点 B / D は画面に触れるため、ユーザー希望時に実施する。
- 性能試験。意図的な性能変更を含まないため。

## 完了条件

1. 全観点の確認項目が期待どおり。
2. 最終の品質ゲートがベースラインと一致（type-check 5/5 / lint 0 error /
   テスト 1269 件＋観点 D の追加分）。
3. 追加・変更したテストがある場合、その理由が最終報告に記載されている。

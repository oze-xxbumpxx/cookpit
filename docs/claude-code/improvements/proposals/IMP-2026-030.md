起動条件記述の維持コストが実稼働に見合っていなかった（harness-complexity-audit 事象 4）。
改善案は 15→8〜9 もあったが、セキュリティ観点の独立性を優先し **security-reviewer は単独維持**、

## 原因

IMP-2026-006 で委譲ギャップを埋めるために専門 Agent を追加したが、その後の Codex 委譲中心の
運用では起動条件が狭くほぼ発動しない一方、正典・同期文書の記述は残り続けた。

## 変更案

削除ではなく **archive へ凍結移設**し、責務は統合先の条件付きセクションへ吸収する。

| 凍結                 | 吸収先                                                                            |
| -------------------- | --------------------------------------------------------------------------------- |
| requirements-analyst | orchestrator（要求分析）+ architecture-designer（要件書 Write / current-feature） |
| performance-designer | architecture-designer（L3・外部 I/O / 大量データ時のパフォーマンス節）            |
| e2e-test-implementer | test-designer（L3・基盤整備済み時の E2E 再委譲）                                  |
| document-reviewer    | reviewer（文書レビュー観点）                                                      |

security-reviewer は単独維持。

## 変更差分（適用内容）

- `.claude/agents/` から 4 定義を `docs/claude-code/archive/agents/` へ `git mv`
- 統合先 4 Agent 定義を更新（tools / 条件付き節 / フロー）
- 正典: orchestration-policy / agent-responsibilities / development-workflow / README /
  usage-guide
- Skill: classify-change / create-requirements-document / create-design-document
- Hook: validate-agent-config.mjs（`AGENT_TOOL_ALLOWED` から reviewer を除去）
- docs/requirements/README.md

## リスク

- 副作用: 統合先定義の肥大 → 条件付き節は起動条件 + 観点リストに限定済み
- eval / 過去ログ・accepted IMP は歴史記録として旧名称を残す（ライブ正典のみ更新）
- 指示過多: 吸収は「発動時のみ読む」節とし、常時必須指示は増やさない

## 評価方法

- 機械: `validate-agent-config` 相当で Agent 名重複なし・参照先 Agent が `.claude/agents/` に存在
- 運用: 次の L2/L3 で旧 Agent 名への委譲が起きないこと、requirements / パフォーマンス / E2E /
  文書レビューの責務が統合先で欠落しないこと
- 既存 eval ケースの期待文言に旧 Agent 名が残る場合は、ケース更新を follow-up とする
  （本 IMP ではライブ正典の整合を優先）

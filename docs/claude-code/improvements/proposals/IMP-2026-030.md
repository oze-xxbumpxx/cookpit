# IMP-2026-030: 改善サイクルの減速（早期昇格禁止・candidate アーカイブ・meta_work_ratio）

> harness-personal-light-mode Phase2。承認境界は improvement-cycle.md §承認境界 を参照。

- **ステータス**: accepted（本 PR・ユーザー「最善策で着手」承認 2026-07-26）
- **対象 Agent または Skill**: memory-policy.md / improvement-cycle.md / metrics/_TEMPLATE.yml
- **承認区分**: 人間承認必須（改善サイクルの判断基準変更）
- **起票日**: 2026-07-26
- **元候補**: candidates/harness-complexity-audit.md（事象 5）

## 背景

約 3 週間で IMP が多数発生し、後半は「過去改善の後始末」比率が上昇。改善サイクル関連の
構成物が開発ワークフロー本体より重くなっている（harness-complexity-audit 事象 5）。

## 観測事象（根拠）

| 事象 | 再現タスク | 累計回数 | 昇格条件 |
| ---- | ---------- | -------- | -------- |
| 改善の後始末型 IMP の連発 | IMP-018/021/024/026 系譜 | 構造的 | 作業/トークンの継続的浪費 |
| candidate が単調増加し archive 基準なし | harness-complexity-audit | 構造的 | 同上 |
| 例外的早期昇格の常態化 | IMP-012 前例の反復 | 複数 | 同じ問題が繰り返す |

## 原因

昇格の例外が常態化し、対応済み候補のアーカイブ基準が無く、メタ作業量を測る指標が無い。

## 変更案

1. 早期昇格を原則禁止（3 回蓄積を厳守）。例外は「確証あり・修正極小」を 1 行だけ残す
2. 対応済み candidate を `candidates/archive/` へ移す基準を memory-policy へ追加
3. metrics に `process.meta_work_ratio` を追加

## 変更差分

正本は本 PR の memory-policy.md / improvement-cycle.md / metrics/_TEMPLATE.yml /
candidates/archive/README.md。

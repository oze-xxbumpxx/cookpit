# IMP-2026-006: 不足サブエージェント3種の追加と障害設計の設計前倒し

> ユーザー要求による改善。dry run（agent-evaluator）で回帰評価済み・人間承認済み・本適用済み。
> 承認境界は [../../improvement-cycle.md](../../improvement-cycle.md) §承認境界 を参照。

- **ステータス**: accepted（人間承認済み・本適用済み 2026-06-27）
- **承認区分**: 人間承認必須（Agent 定義の新設・ツール権限・委譲フロー変更を含む）
- **起票日**: 2026-06-27
- **元候補**: ユーザー要求（「オーケストレーションからサブエージェントの委譲で何かが足りないか」分析）

## 背景

現状の orchestrator 委譲フローにおいて以下の品質・セキュリティギャップを特定した。

1. `reviewer` にセキュリティ観点が1行しかなく、Web API のコードレベルセキュリティレビュー深度が不足。
2. 外部I/O・大量データを伴う変更のパフォーマンス設計が設計フェーズで明示されない。
3. E2E テストの実装担当が明確でなく、`implementer` に集中しすぎていた。
4. 外部I/O 変更時の障害設計（retry/timeout/冪等性/部分失敗/fallback）が設計書テンプレートに存在せず、
   `reviewer` が事後発見するまで設計書に残らない構造だった。

## 変更内容

### 新規エージェント（`.claude/agents/`）

| ファイル | 起動条件 | 位置 |
|---|---|---|
| `security-reviewer.md` | L2/L3 全タスク（コード変更ありの場合）で reviewer の後 | 新規 |
| `performance-designer.md` | L3・外部I/O or 大量データ条件のみ、architecture-designer 後 | 新規 |
| `e2e-test-implementer.md` | L3・Playwright/Hono テスト基盤整備済み条件のみ、implementer 後 | 新規 |

### 更新ファイル

- `.claude/agents/orchestrator.md`: tools リストと委譲フロー（L2/L3）に新3エージェントを追加
- `docs/claude-code/agent-responsibilities.md`: 一覧表・権限注記・責務セクションを更新
- `docs/claude-code/orchestration-policy.md`: 委譲フロー図・新エージェント起動トリガー・モデル表を更新
- `.claude/skills/create-design-document/SKILL.md`: 手順6に外部I/O時の障害設計必須項目(a)-(e)を追加

## 設計判断

- `security-reviewer` は `reviewer` と役割分担（品質全般 vs. セキュリティ専門）で重複を排除。
- `performance-designer` / `e2e-test-implementer` は条件付き起動を orchestration-policy.md・
  orchestrator.md・各 Agent 定義の3箇所に一貫して記載し、L1/L0 での過剰工程を防止。
- `create-design-document` Skill への障害設計追加は「reviewer から設計フェーズへの前倒し」であり、
  reviewer の (a)-(f) チェックリストは残す（独立した安全網として機能させる）。

## リスク

- L2/L3 で security-reviewer が必須化されることによるトークン増。
  → dry run 評価で「起動条件を満たした必要な増加」と判定済み（Agent 呼び出し効率 横ばい）。
- performance-designer / e2e-test-implementer が条件を無視して起動するリスク。
  → 複数箇所への一貫した起動条件記載で構造的に担保されていることを dry run で確認済み。

## 背景

多段 background 委譲（Orchestrator を子エージェントとして経由する形を含む）が実運用で
安定せず、「子 Agent の成果物なし完了」→ メインセッションによる Orchestrator 役の代行、
というパターンが反復している。一方、この不安定さへの補強として積まれた stop/resume・
`inflight-agents.json`・冪等再開の機構（IMP-2026-007/008/009）が orchestration-policy 肥大
（352 行）の主因になっている。実際に安定稼働している型は
**「メインセッションが Orchestrator 役を務め、専門 Agent を直接起動。実装は Codex 委譲または
implementer」**であり、正典をこの実態に合わせて縮約する。

## 観測事象（根拠）

| 事象                                                            | 再現タスク                                     | 累計回数 | 昇格条件        |
| --------------------------------------------------------------- | ---------------------------------------------- | -------- | --------------- |
| stop/resume 後の notification 待ちループ                        | store-master（事象 1・2026-06-28）             | 1        | 同系統 3 回以上 |
| 単一委譲でも background 化・同期待機前提の崩れ                  | meal-plan-screens（事象 4・2026-07-09）        | 2        | 同上            |
| 多段 background 委譲で「成果物なし完了」×2 → メインが代行へ切替 | pantry-screens（logs/2026-07-19 セッション 2） | 3        | **充足**        |

## 原因

恒久的・構造的。ハーネス側の子エージェント通知配送・background 挙動（orchestration-policy
§既知の制約に記録済み）は Cookpit の Agent 定義では修正できない。これに機構追加で対抗した
結果、最も複雑な部品（多段委譲 + stop/resume 機構）が最も使われない状態になった。

## 変更案

**追加ではなく削除・移動。** 3 点で構成する。

1. **正規ルートの明記**: 「Orchestrator 役はメインセッションが務める」を正典化する。
   - ローカル: `claude --agent orchestrator`（従来どおり・メインセッション起動）。
   - リモート: 通常セッションが orchestration-policy に従い専門 Agent を直接起動する
     （2026-07-19 に実際に機能した型）。
   - **Orchestrator 自体を Agent ツールの子として起動する多段委譲は行わない**
     （現行「既知の制約」の運用注記を禁止事項へ昇格）。
2. **stop/resume 機構の凍結**: §stop/resume を跨ぐ委譲の扱い（約 23 行）と既知の制約 3 節
   （約 41 行）を `docs/claude-code/archive/orchestration-frozen-mechanisms.md` へ**移動**
   （削除しない。ハーネス側の挙動が改善されたら復元判断）。`inflight-agents.json` の運用は停止。
   本文には次の 1 原則だけを残す:
   > **resume・再開直後は notification を待たず、期待成果物の存在・更新時刻で完了を冪等判定
   > してから次を決める（無ければ再委譲・二重起動しない）。**
   > （IMP-2026-009 の一般化。この原則単体で機能した実績: meal-plan-screens 2026-07-09 /
   > pantry-screens 2026-07-19）
3. **orchestrator.md の縮約**: 進め方 3 の `inflight-agents.json` 分岐（約 8 行）と
   進め方 4 の resume 分岐詳細（約 10 行）を、上記 1 原則への参照 2 行へ置換。

削減見込み: orchestration-policy 約 60 行（352 → 約 290 行）+ orchestrator.md 約 16 行。
委譲フロー・並列指針・各 Agent 起動条件・モデル采配は**変更しない**。

## 変更差分 v2（v1 の評価悪化を受けた改訂・2026-07-20）

v1 の 1 原則は「直前に委譲した Sub-agent」という**単数前提**の文言で、L3 の
`planner ∥ test-designer` のような並列 background 委譲の部分完了判定を明示的にカバー
していなかった（evaluator 指摘。IMP-2026-008 v1→v2 と同型の修正パターン）。v2 は
機構を復活させず、**1 原則を複数形へ一般化**する:

> resume・再開直後は notification を待たず、**直前までに委譲した未確認の Sub-agent
> すべてについて、それぞれの期待成果物の存在・更新時刻で完了を冪等判定してから次を
> 決める**。完了した分は次工程へ進め、未完了のものだけを再委譲する（並列 background
> 委譲の部分完了では、完了済み Sub-agent を再起動しない）。単一委譲・並列委譲を問わず
> 適用する。

orchestrator.md（ローカル適用待ち分）の縮約文も同じ複数形文言に合わせる:

```diff
--- .claude/agents/orchestrator.md（進め方 4 の置換文・v2）
+   - resume・再開直後は、直前までに委譲した未確認の Sub-agent すべてについて期待成果物の
+     存在・更新時刻で完了を冪等判定し、完了分は次工程へ・未完了分のみ再委譲する
+     （正典: orchestration-policy.md §再開時の完了判定）。
```

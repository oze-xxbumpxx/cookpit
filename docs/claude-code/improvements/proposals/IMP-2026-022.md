- **対象 Agent または Skill**: Skill: kickoff-session
- **承認区分**: manager レビュー後可（非破壊・軽微＝Skill チェック項目追加）。**ただし guard-dangerous

## 背景

shopping-list-screens で、前セッション（2026-07-13）が usage リミットで強制中断した後、別セッション
（2026-07-14）が `logs/2026-07-13.md` と `git ls-remote` によるリモートブランチ確認だけで中断点を
正確に復元し、残工程のみを二重作業ゼロで再開できた。この「日次ログ + Git 上の成果物確認だけで
セッションを跨いだ引き継ぎが機能した」パターンは広義で累計 3 回目（test-infra-expansion の計画的
分割・shopping-list-core 事象 9・今回）。ただし今回は **usage リミットによる強制中断からの復旧**
という新しい性質と、「チェックポイントコミット + `git ls-remote`」という新規手段が加わっている。
現状この手順は各セッションが経験的に再発明しており、明文化されたチェックリストがない。

あわせて事象 7（PR 集約先ブランチの二重化: 前セッションの `feature/*` と再開セッションの
`claude/<slug>` が並存し、PR をどちらへ集約するかユーザー確認が必要になった）は、同じ
「強制中断→別セッション再開」シナリオで顕在化した同系統の問題であり、復旧手順に統合する。

## 観測事象（根拠）

| 事象                                                | 再現タスク                                                               | 累計回数  | 昇格条件                           |
| --------------------------------------------------- | ------------------------------------------------------------------------ | --------- | ---------------------------------- |
| ログ + Git 成果物確認だけでセッション跨ぎ復旧が機能 | test-infra-expansion / shopping-list-core(事象9) / shopping-list-screens | 3（広義） | 成功パターンが複数タスクで再現した |
| 強制中断→別セッション再開でブランチ二重化           | shopping-list-screens（事象 7）                                          | 1         | 事象 1 に統合（単独では未昇格）    |

## 原因

**恒久的な構造的要因（手順の未明文化）**。復旧が機能したのは (a) フェーズ境界のチェックポイント
コミット、(b) 日次ログの中断理由・完了フェーズ・残工程が判別可能な粒度、(c) リモートブランチ
という「セッションを跨いでも消えない情報源」を確認する習慣の 3 つが揃ったため。これらが暗黙知の
ままだと再発明コストがかかり、ブランチ二重化のような取りこぼしも起きる。

## 変更案

**最小変更（1 Skill・kickoff-session 手順 1 へのサブ項目追加）**。復旧は次セッションの**開始時**に
起きるため、セッション開始段取りの正典である kickoff-session Skill が自然な置き場所。
development-workflow.md への新規節追加も検討したが、(1) 手順は Skills に分離する方針
（memory-policy.md §肥大化対策）、(2) kickoff-session 手順 1 は既に「前回ログ + git 状態の
ブリーフィング」を扱っており重複なく差し込める、(3) development-workflow.md を痩せ保つ、という
理由で **Skill 側に寄せる**（development-workflow.md は変更しない）。事象 7 は独立節にせず、
同じ復旧サブ項目に「前セッションの成果ブランチ確認・同一ブランチ継続判断」として統合する。

## 背景

タスク品質メトリクス（`improvements/metrics/*.yml`）は IMP-2026-007 の「定量 after 計測後に
採否を最終判断する」という条件付き採用の前提だが、実体は 2 件（TASK-2026-001/002）しか
存在せず、計測がほぼ回っていない。

## 原因（構造的）

計測経路が**セッションを跨いだ揮発状態に依存**している。

- SubagentStop Hook → `.claude/state/subagent-log.jsonl`（**非コミット・エフェメラル**）
- `collect-task-metrics.mjs` がこのログを読んで `metrics/*.yml`（コミット対象）へ転記
- リモート環境ではコンテナ回収と同時に subagent-log が消えるため、
  「後からまとめて集計」は構造的に不可能。close-session を通らず終わったセッションの
  データは永久に失われる。

## 変更案（2 案・推奨は A）

### 方針 A（推奨）: セッション内確定の原則

「計測データはセッション終了前にコミット対象ファイルへ確定する」を原則化する。

1. orchestrator: L3 タスクで Sub-agent 委譲が完了するたび（または全委譲完了時）、
   `record-task-metrics.sh` + `collect-task-metrics.mjs --write` を実行して
   `metrics/<TASK>.yml` へ即時転記する（reflection-agent 起動を待たない）。
2. close-session Skill: メトリクス転記を「feature 未完了でも machine セクションだけは実行」
   に変更する（現状は feature 完了時に先送りされ、そのままセッションが消える）。
3. 横断集計・振り返りはコミット済み `metrics/*.yml` のみを入力とする
   （subagent-log を過去に遡って読む期待を improvement-cycle.md から削除）。

### 方針 B: 定量計測の簡素化（諦める判断）

Sub-agent 単位のトークン・ツール数計測を放棄し、活動ログ + コミットベースの
`estimate-session-time.mjs`（日単位の所要時間）と品質メトリクス（手戻り回数・レビュー指摘数 =
reflection-agent が成果物から抽出可能）だけに一本化する。IMP-2026-007 の「定量 after 計測」は
所要時間 + 工程数の粗い比較に切り替える。

### 比較

| 観点                    | 方針 A                               | 方針 B                         |
| ----------------------- | ------------------------------------ | ------------------------------ |
| IMP-2026-007 の定量判断 | トークン/ツール数まで可能            | 所要時間ベースの粗い判断のみ   |
| 追加の運用負荷          | 委譲毎の転記（orchestrator 指示 +1） | ほぼゼロ（既存の推定に一本化） |
| 変更対象                | Skill 2 + Agent 1 + 正典 1           | 正典 1（期待値の削除）のみ     |
| 失敗モード              | close-session 前の強制終了で部分欠損 | 定量の解像度が恒久的に下がる   |

## 実地トライアル（2026-07-09・meal-plan-screens L2 で方針 A を試行）

セッション内転記は**動作した**（`metrics/TASK-2026-003.yml` にセッション 1 件・活動 51 分・
tool_uses 168・agent_calls {implementer:1}・トークン内訳を確定）。ただし素の実行では
0 件集計になり、2 つの前提条件が判明した。A 採用時は以下も反映すること。

1. **`current-feature` は Sub-agent 委譲の前に書く**。SubagentStop Hook は記録時点の
   `.claude/state/current-feature` を読むため、後から書いても `feature: null` のままになる
   （今回発生。orchestrator の委譲手順に「委譲前に current-feature 設定」を明記する）。
2. **ブランチ相関は既定（feature 名の部分一致）ではリモート自動命名ブランチ
   （`claude/<任意>-<suffix>`）にマッチしない**。`collect-task-metrics.mjs --branch <実ブランチ部分文字列>`
   の明示が必要（または current-feature 経由の session 相関で拾えるよう 1 を徹底する）。

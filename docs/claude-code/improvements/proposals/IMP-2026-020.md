## 原因

**恒久的な構造的要因**。現在の create-codex-brief SKILL.md は、手順 4 に「命名の明示（DB テーブルは
複数形など傾向ずれが既知のもの）」を含め、テンプレートにも「## 命名・記法の注意」節を持つが、
(a) この節が**必須**であることが明示されておらず、(b) 内容を「feature / 層で実際に出た過去指摘から
抽出する」という運用が書かれていない。Task 3・Task 5 で効いたのは、この節を feature 固有の既知
ミス型（Hono ルート変数の複数形・`bought`/`target-store` の綴り・`result.created ? 201 : 200` の
三項の向き・2 バリデータの明記など）で埋めたためであり、汎用チェックリストのコピペでは同じ効果は
出ない。「暗黙のうちに効いていた成功要因」を明文化して形骸化を防ぐのが本改善。

## 変更案

**最小変更（1 Skill・追加のみ、削除なし）**。指示の追加ではあるが、既存の曖昧な 1 行
（「命名の明示」）を**必須節への言及に置換**し、テンプレートの既存節に必須マークと抽出元の
明示を足すだけ。新規手順は増やさない。過剰化を避けるため「汎用コピペ禁止・feature 固有に限る」
という**歯止め**を同時に書き、指示書肥大化・形骸化のリスクに対処する。

## リスク

- 副作用: 指示書作成の工数がわずかに増える（feature 固有の過去指摘を拾う手間）。ただし既に
  Task 3・5 で実践されており、追加コストは限定的。他 Agent への影響なし（Codex ルート専用 Skill）。
- 指示過多の懸念: 節を「必須」にすることで、過去指摘が乏しい新規 feature でも埋めようとして
  汎用コピペが混入する恐れ → 差分に「汎用コピペ禁止・feature 固有に限る」の歯止めを明記して対処。
  空欄でも「特記なし」と書けるよう運用を許容する（完了条件は「埋まっている」＝特記なしも可）。

## 適用の制約（重要）

本 proposal は軽微カテゴリ（manager 後可）だが、`.claude/skills/` は guard-dangerous.mjs
（IMP-2026-013 で警告→ブロックに格上げ）の保護対象であり、agent-improvement-manager からの
Write は `.claude/state/config-change-approved` マーカーが無い限りブロックされる。manager は
このマーカーを独断で作成できない（Hook のブロック条件の回避は人間承認必須）。したがって本件は
**差分提示のみ・未適用**とし、人間が承認・マーカー作成のうえメインセッションで適用＋コミットする。

## ロールバック方法

- 対象は SKILL.md の 1 節のみ。適用コミットを `git revert` するか、当該差分を手で戻す。
- 副作用（指示書肥大化）が観測されたら、必須マークを外し「推奨」に戻す（節自体は残す）。

## 背景

同一のコーディング規約・アーキテクチャ原則が「正典（`.claude/rules/`）+ CLAUDE.md 要約 +
Agent 定義内の再掲 + Skill テンプレ内の抜粋」に多重コピーされており、正典を修正するたびに
衛星の同期漏れが再発している。IMP-2026-018（反映先一覧欄）は起票プロセス側の対症療法であり、
コピーの本数そのものは減っていない。

## 観測事象（根拠）

| 事象 | 再現タスク | 累計回数 | 昇格条件 |
| ---- | ---------- | -------- | -------- |
| 委譲フロー記述が 5 文書で不一致 | skills-inventory-audit（事象 2） | 1 クラス目 | 同じ問題（要約コピーの同期漏れ）が 3 クラス以上 |
| default export 例外が衛星 3 文書（CLAUDE.md / implementer / create-codex-brief）未同期 | harness-post-020-audit（事象 1） | 2 クラス目 | 同上 |
| orchestrator.md が正典追記（IMP-020 #6）のポインタを欠落 | harness-post-020-audit（事象 6） | 3 クラス目 | **充足** |

## 原因

恒久的・構造的。「正典 + N 衛星に要約コピー」という設計自体が N 文書同期を必然化しており、
反映先一覧（IMP-2026-018）はヒューマンプロセスでの緩和にすぎない。コピーの本数を減らす
以外に再発クラスは消えない。

## 変更案

**追加ではなく削除。** 規約の同期面を次の 2 点だけに縮小する。

- **正典**: `.claude/rules/`（coding-standards / domain-layer / presentation-layer）
- **唯一の要約**: CLAUDE.md §アーキテクチャ原則（常時ロードされる唯一のコンテキストのため維持。
  `.claude/rules/` は自動ロードされない — rules/README.md 参照）

Agent 定義内の規約再掲（implementer / architecture-designer）は削除し、「着手前に正典を
Read する」指示へ置換する。Subagent には CLAUDE.md（要約）が届いており、正典 Read の
明示指示で詳細を担保する（rules は 28〜47 行と小さくトークン影響は軽微）。

**意図的に変更しないもの**:

- `create-codex-brief/SKILL.md` の規約抜粋指示（L42-44）: Codex は外部実行者で
  `.claude/rules/` を読めないため、ブリーフへの自己完結な抜粋は**機能要件**。ただし抜粋には
  「正典: coding-standards.md」の出典明記を維持する（既に対応済み）。
- CLAUDE.md §アーキテクチャ原則: 上記のとおり唯一の要約として維持。以後の正典修正時の
  同期対象はこの 1 箇所のみになる。

## リスク

- 副作用: Subagent が正典 Read を省略した場合、規約詳細（default export 例外等）を
  見落とす可能性 → 「Read してから着手する」を厳守文言にし、reviewer の既存観点
  （コーディング規約準拠）で担保。CLAUDE.md 要約は引き続き届く。
- 指示過多の懸念: なし（正味削減。implementer 約 13 行 / architecture-designer 約 5 行減）。

## 評価方法

- 対象 eval ケース: 既存の実装系ケース（frontend-screen-addition 等 `.claude/evals/cases/`）で
  before/after 採点。「page.tsx の default export を禁止と誤判定しない」を含む実装整合性軸。
- 観測軸: 実装整合性 / レビュー品質 / トークン効率（悪化 1 軸でも不採用）。
- 実運用確認: 次回の正典（rules）修正時に、同期作業が CLAUDE.md の 1 箇所で済むこと。

## 評価結果

- **v1（2026-07-20・agent-evaluator・[evaluations/IMP-2026-027.md](../evaluations/IMP-2026-027.md)）: 不採用**。
  トークン効率が 3 ケース全てで悪化（-1。rules 3 ファイル無条件 Read +69〜97 行相当が

  default export 誤判定回避は CLAUDE.md（IMP-2026-020 適用済み）で既に担保されており
  本提案の追加便益ではない。domain 規約の改善（database-schema-change で +1）は
  他ケースの悪化を相殺しない（軸ごと個別判定）。
- **v2（2026-07-20・同 3 ケース・evaluations/IMP-2026-027.md「v2 再評価」節）: 採用推奨**。
  v1 の悪化（無条件 Read によるトークン効率 / L1 不要作業量）は v2 に該当構造が無く解消。
  全軸 before 以上・劣化指標は横ばい〜微減。残存指摘 2 点（非ブロッキング）:
  ① default export 例外の完全なファイル一覧が衛星から消え「条件付き正典参照」の非決定的
  担保になる点は現行 eval セットでは検証不能（page.tsx 以外の App Router 特殊ファイルを
  扱う eval ケースの拡充を推奨）。② v1 で観測された database-schema-change の domain 規約
  改善（+1×2 軸）は v2 では発生しない（before 水準への回帰であり悪化ではない）。

## 採用または却下理由

- v1: 2026-07-20 却下（回帰評価で 2 軸悪化 — improvement-cycle §回帰評価の方法の規律どおり）。
- v2: **2026-07-20 採用**（回帰評価で悪化ゼロ。人間承認は同日の 3 件採用承認
  〔「悪化時は短縮版 + ポインタの代替案」を含む推奨への承認〕に基づく）。
  適用は対象 2 ファイルが保護構成ファイルのためローカル適用バッチ（backlog 申し送り）で実施。
  適用後、次回の App Router 特殊ファイルを含むタスクで default export 例外の判断劣化が
  ないか実地確認する（残存指摘 ① の追跡）。

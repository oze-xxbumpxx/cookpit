## 原因

**恒久的・構造的原因。** create-test-plan Skill は「正常系・異常系・境界値・整合性・冪等性・回帰」を
標題には掲げているが、本文の必須化は「異常系・境界値」までで、(1) 冪等性、(2) 障害系（外部依存の
失敗・タイムアウト・部分失敗・リトライ）、(3) フロントエンド固有（ローディング・エラー表示・楽観的
更新のロールバック）が**具体的なチェック項目として落ちていない**。このため障害設計が核心の
`external-service-failure` や回帰確認が核心の `refactoring` で観点が抜ける。

## 変更案

最小変更で最大効果を狙い、変更対象は `create-test-plan/SKILL.md` の **1 ファイルのみ**。
指示を「増やすだけ」にしないため、追加観点には必ず**観点の選択基準（適用条件）**をセットで付ける。
これにより L1 / domain 純粋ロジックなどでは不要な観点を**適用しない**ことを明文化し、
過剰工数化（不要作業量・トークン効率の悪化）を防ぐ。すなわち「追加」と同時に「適用範囲の限定」を
入れる設計で、肥大化＝追加ではない原則を満たす。

- 手順 3 に観点(4)(5)(6)を追加し、各観点に**適用条件**を併記。
- 「観点の選択基準」セクションを新設し、変更レベル・対象層でフィルタする表を置く。
- テンプレートの「特性観点」を拡張（障害系・FE 固有を任意追加欄として用意）。
- 完了条件に「対象層・レベルに該当する観点だけが含まれている（過剰適用がない）」を追加し、
  網羅と過剰の両方向を完了条件で締める。

> CLAUDE.md・Agent 定義・Hook・セキュリティルールには一切触れない。Skill のチェック項目追加・
> テンプレ改善のみであり、承認区分は「manager レビュー後可（非破壊・軽微）」。

## リスク

- 副作用: 他 Agent への破壊的影響なし。Skill は test-designer のみが使用。CLAUDE.md・
  各 rules・Hook・Agent 定義を参照／変更しないため指示競合は生じない。
- 指示過多の懸念: 観点を**無条件追加**すると L1・domain 純粋ロジックで試験計画が肥大化し
  不要作業量・トークン効率が悪化する。これを「観点の選択基準」表（L1・Domain 純粋は原則対象外、
  該当しない観点は「対象外」と明記して飛ばす）で打ち消す設計とした。追加と限定を同一提案に
  含めることでネットの指示負荷増を抑える。

## 評価方法

- 対象 eval ケース:
  - `.claude/evals/cases/external-service-failure.md`（障害系・冪等性が核心 → 網羅性向上を確認）
  - `.claude/evals/cases/refactoring.md`（回帰観点 → 網羅性向上を確認）
  - `.claude/evals/cases/small-bug-fix.md`（L1 → 過剰適用が起きていないか＝不要作業量・トークンの
    悪化が無いかの回帰確認）
- 観測軸: テスト網羅性（改善期待）/ 不要な作業量・トークン効率（悪化しないこと）/ 要件理解・
  実装整合性・レビュー品質（中立であること）。
- 判定ルール: improvement-cycle.md §回帰評価。**1 軸でも悪化があれば不採用。**

## 評価結果

agent-evaluator のレポート: [../evaluations/IMP-2026-001.md](../evaluations/IMP-2026-001.md)。

- `external-service-failure`: テスト網羅性 2 → 4（+2）。他軸は中立、悪化なし。
- `refactoring`: テスト網羅性 2 → 3（+1）。不要作業量・トークン効率は中立（選択基準が「回帰観点
  最優先」で抑制）、悪化なし。
- `small-bug-fix`（L1 過剰適用チェック）: テスト網羅性 2 → 2（中立）。不要作業量・トークン効率とも
  5 → 5 で悪化なし（選択基準「L1 は原則対象外」が機能し肥大化を防止）。

**全ケース・全軸で悪化ゼロ。** 改善は障害系・回帰観点ケースに限定して現れ、L1 では中立。
選択基準による過剰適用防止が意図どおり機能した。

> guard-dangerous Hook の承認マーカー個別承認）のうえ本適用した簡易フロー。
> 承認境界は [../../improvement-cycle.md](../../improvement-cycle.md) §承認境界 を参照。

- **ステータス**: accepted
- **対象 Agent または Skill**: Agent: reviewer / security-reviewer / document-reviewer / orchestrator、docs: orchestration-policy.md / CLAUDE.md / docs/claude-code/{README,usage-guide}.md（Agent モデル早見表の同期）
- **承認区分**: 人間承認必須（Agent のモデル・ツール権限の変更のため）
- **起票日**: 2026-07-05
- **元候補**: ユーザー要求（モデル采配役の運用ポリシー組み込み依頼。candidate ファイルなし）

## 背景

作業内容に応じて Haiku / Sonnet / Opus / Fable を使い分け、品質を保ったままトークン消費を
抑える「モデル采配」ポリシーの組み込み要求。調査の結果、モデル指定の受け皿（全 15 Agent の
frontmatter `model` + orchestration-policy.md §モデル割り当て）は既存だが、次の 4 ギャップが
あった。

1. Haiku 層が未使用（orchestrator が検索・ファイル確認を自分 = Opus で実行）
2. レビュー系 3 Agent（reviewer / security-reviewer / document-reviewer）が「判断がいる作業 =
   Opus」の采配基準に反して Sonnet のまま
3. Fable 層が未定義（frontmatter・切替ガイドのどちらにも登場しない）
4. 「作業前のモデル采配表提示」「メインモデル切替の提案」という運用ルールが未定義

## 変更内容（本適用済み）

1. `.claude/agents/{reviewer,security-reviewer,document-reviewer}.md`:
   `model: claude-sonnet-5` → `claude-opus-4-8`
2. `.claude/agents/orchestrator.md`: `Agent(...)` 許可リストへ組み込み `Explore` を追加、
   「進め方」へ采配表提示を追記、「モデル采配」節（Explore/haiku 委譲・L3 Fable
   オーバーライド・メイン切替提案基準）を新設
3. `docs/claude-code/orchestration-policy.md` §モデル割り当て: 4 層の采配基準・禁止事項 3 点・
   早見表更新・Fable の使い方（L3 限定）・メインモデル切り替えガイドを追加
4. `CLAUDE.md`: 開発ワークフロー節にモデル采配の正典参照を 1 文追加（あわせて Prettier に
   よる「参照ドキュメント」表の列幅再整形が同ファイルに入っている。内容変更なし）
5. `docs/claude-code/README.md` / `docs/claude-code/usage-guide.md`: Agent モデル早見表の
   reviewer / security-reviewer / document-reviewer 行を `opus-4-8` へ同期
   （document-reviewer の初回 Opus レビューで検出された更新漏れ Must-1 の反映）

コスト設計：昇格は呼び出し頻度の低い判断系 3 Agent のみ。実装・定型系 10 Agent は Sonnet
据え置き。検索を Opus（orchestrator 自身の Read/Grep）から Haiku（Explore）へ下げるため
差し引きで抑制方向。agent-evaluator は定型評価・高頻度のため Sonnet 据え置き。

## 採用しなかった案

- document-reviewer の Sonnet 据え置き（采配基準の一貫性を優先し不採用）
- architecture-designer の Fable 固定（L2 でも Fable が動きコスト増のため不採用。
  L3 のみ呼び出し時オーバーライド）
- Fable をメイン切替のみで運用（L3 設計品質の向上機会を逃すためフォールバック扱い）

## リスク・既知の注意

- Agent 呼び出しの `model` パラメータオーバーライドは CLI バージョン依存の可能性 →
  ポリシーにフォールバック（メイン切替提案）を明記済み。
- Agent 設定チェック Hook が「参照先 Agent が存在しません: Explore」と警告するが、
  Explore は Claude Code の組み込み Agent（ローカル定義不要）のため**誤検知**。
  orchestration-policy.md §モデル割り当てに注記済み。Hook 側の組み込み Agent 許容リスト
  対応は別途改善候補（軽微・非ブロックのため急がない）。

## 評価方法

- 次の L2/L3 タスクで確認：(a) orchestrator が委譲前に采配表を提示するか、
  (b) 検索系調査が Explore(haiku) へ委譲されるか、(c) L3 で architecture-designer の
  Fable オーバーライドが効くか（効かなければフォールバック発動を確認）、
  (d) reviewer 系が Opus で起動するか。
- reflection-agent の振り返りでトークン消費の変化を記録し、昇格 3 Agent のコスト増と
  検索委譲の削減効果を突き合わせる。

## 採用または却下理由

**採用（2026-07-05・人間承認）**。プランモードで全変更差分を提示しプラン承認を取得。
保護 Hook（guard-dangerous.mjs）の承認マーカー作成も AskUserQuestion で個別承認を得て実施
（マーカーは作業後に削除済み）。

  ポリシー文書 + CLAUDE.md 1 文 + 早見表 2 文書の同期のみで、コード・スキーマへの
  影響なし）。

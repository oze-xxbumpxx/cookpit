# IMP-2026-016: L2 security-reviewer の省略条件を明文化

> Agent 起動条件の変更のため人間承認必須。過剰工程（Opus 常時起動）の抑制。

- **ステータス**: accepted
- **対象 Agent または Skill**: docs: orchestration-policy.md / orchestrator.md / agent-responsibilities.md / classify-change Skill ほか同期文書
- **承認区分**: 人間承認必須（成果物の省略条件・Agent 起動条件）
- **起票日**: 2026-07-08
- **採用日**: 2026-07-08
- **元候補**: ハーネス改善相談（2026-07-08）P1-3

## 背景

IMP-2026-006 で L2/L3 全タスクに security-reviewer を必須化した後、IMP-2026-014 で
レビュー系を Opus に昇格した。結果として Presentation のみ・契約不変リファクタ・テスト基盤のみ
の L2 でも Opus の security-reviewer が常時起動し、トークンコストが過剰になりやすい。

## 変更内容

正典は `docs/claude-code/orchestration-policy.md` §security-reviewer。

- **必ず起動**: 認証/秘密情報/外部 I/O/依存追加・メジャー更新/入力境界の未検証リスク/L3 全層変更
- **L2 で省略可**: Presentation のみ or 契約・DB・認証に触れない内部リファクタ/テスト基盤のみ、
  かつ依存追加なし・秘密情報/外部 I/O/認証なし。省略時は最終報告に理由 1 行。
- 迷ったら起動側に倒す。

## ドライラン判定表

| ケース                                          | レベル | security-reviewer | 根拠                                      |
| ----------------------------------------------- | ------ | ----------------- | ----------------------------------------- |
| frontend-screen-addition（既存 API の画面追加） | L2     | 省略可            | Presentation 中心・契約不変・依存追加なし |
| refactoring（振る舞い不変）                     | L2     | 省略可            | 契約・DB・認証不変                        |
| api-field-addition（Zod/DB 境界変更）           | L2     | **必須**          | 入力境界の変更                            |
| database-schema-change                          | L3     | **必須**          | L3 全層                                   |
| documentation-only-change                       | L0/L1  | 起動しない        | コード変更なし                            |

## ロールバック

orchestration-policy.md の §security-reviewer を「L2/L3 全タスクで必ず起動」に戻し、
同期した早見表・classify-change・agent-responsibilities も旧文言へ戻す。

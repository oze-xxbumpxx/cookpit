## 観測した事象

### 事象 1: Stop hook（close-session ナッジ）の所要時間未記録判定が「記録なし」の部分一致で誤検出

- **種類**: 手戻り（誤ナッジ起因の調査・ログ修正コミットが発生）
- **観測した事象**: `logs/2026-07-06.md` の所要時間欄に「約 30 分（…先行セッションは記録なし）」と
  記録済みだったにもかかわらず、`timeUnrecordedNudge()` が「未記録」と判定し close-session ナッジが
  発火した。判定は `/記録なし|\[作業時間\]/` のセクション内**部分一致**のため、別文脈の
  「記録なし」（先行セッションへの言及）に反応した。
- **発生回数**: 1（本ナッジは R5 として 2026-07-06 導入・PR #41。導入初日の初観測）
- **対象タスク**: meal-plan-core（Task 03 レビューセッション）
- **原因仮説**: 未記録判定が「セクション本文が『記録なし』のみ」ではなく部分一致であり、
  時間が記録済みでも同語が含まれるだけで未記録扱いになる。所要時間欄に注記を書く運用
  （複数セッション日の内訳注記など）と衝突する。
- **改善案**: `.claude/hooks/check-improvement-cycle.mjs` の `timeUnrecordedNudge()` を
  「セクション本文を trim した結果が `記録なし` / `[作業時間]` に一致、または空」の**完全一致**へ変更。
  代替案: 時間表現（`/\d+\s*(分|時間|h)/`）が存在すれば記録済みとみなす判定の併用。
- **変更対象**: Hook（check-improvement-cycle.mjs）
- **想定される副作用**: 完全一致化すると「記録なし（理由付き）」のような行が未記録と扱われず
  ナッジが出なくなる。ただし理由付き未記録は稀で、close-session の自動推定で埋める運用のため影響軽微。
- **評価方法**: IMP-2026-002 / 005 / 011 と同じスクリプト試験方式。修正前後で 3 ケースの
  スモーク: ①「約 30 分（…記録なし言及あり）」→ 発火しない ②「記録なし」のみ → 発火
  ③「[作業時間]」プレースホルダ → 発火
- **昇格判定**: ユーザー指示により候補起票（2026-07-06）。原因確証あり・修正小
  （IMP-2026-011 と同型のパターン）だが、**Hook 変更 = 人間承認必須**のため proposal / 承認待ち。
  当面の回避はログ側の文言変更で適用済み（コミット `4a7799f`）。
  → **2026-07-08 採用・本適用済み**（[accepted/IMP-2026-015.md](../accepted/IMP-2026-015.md)。
  スモーク 6/6 PASS）。

## 発見

### (a) 骨子削除は 027 v2 の採択理由を取り消す

027 v2 が採用されたのは、無条件 Read を足さず、`create()` / `reconstruct()` / 依存方向を
implementer の常時プロンプトに残したからである。変更 B の after ではこの 3 点が
`implementer.md` から消える。L1 の domain 修正（small-bug-fix）は、Subagent が
`.claude/rules/domain-layer.md` を能動的に Read しない限り、骨子を失う。

変更 B は「必読」と書くだけで Read を強制しない。027 v1 は Read を強制してトークンを悪化させ、
変更 B は Read を強制せずに **読み漏れリスク** を残す。どちらも v2 より悪い。

### (b) 例外列挙の再掲は現行で既に無い

`loading.tsx` / `not-found.tsx` 等の完全列挙は `.claude/rules/coding-standards.md` にだけある
（2026-08-12 実測）。変更 B が消そうとしている 6 行は例外列挙ではなく骨子である。
「転換 4（繰り返し記述 → 一本化）」の対象を、既に一本化した例外列挙と取り違えている。

### (c) frontend-screen-addition の例外判断は CLAUDE.md で足りる

CLAUDE.md の「page.tsx / layout.tsx 等は例外」は変更 B の対象外。このケースの default export
判断は before と同じ。スコア上の改善は出ない。

## 総合判定

- **判定**: **採用非推奨（変更 B は却下）**
- **理由**:
  1. small-bug-fix の実装整合性が -1。rubric は 1 軸でも悪化すれば不採用。
  2. 027 v2 が「骨子は Agent 定義に残す / 例外列挙だけ正典へ戻す / 無条件 Read は足さない」
     で悪化ゼロになった。変更 B はそのうち骨子残存だけを取り消す。
  3. 例外列挙の再掲は現行で既に無い。変更 B が消す対象は、一本化済みの繰り返しではなく
     Subagent のフェイルセーフである。

変更 A の採択は維持する。変更 C は提案どおり据え置き。

## 代わりに採用する不変条件（本評価と同時にテスト化）

文章で「再掲するな」と書く代わりに、次を `pnpm test:harness` で固定する。

1. App Router 例外のファイル列挙の正典は `.claude/rules/coding-standards.md` だけ。

# Codex 委譲プレイブック

Codex への実装委譲を「指示書生成 → 実行 → レビュー → 差し戻し」の定型フローとして運用する
ための手順書。**いつ Codex を使うかの判断基準とレビューチェックリストは
[docs/06-ai-tools.md](../06-ai-tools.md) が正典**。本書はその実行手順を担う。
指示書の生成は `create-codex-brief` Skill（`.claude/skills/create-codex-brief/`）が担う。

作成: 2026-07-04（業務改善分析タスク）。

## フロー全体

```
タスク開始（kickoff-session）
  └─ 実装ルート宣言: 「指示書に書き切れるなら Codex」（06-ai-tools）
       │
       ├─ Codex 委譲ルート
       │    1. Claude Code: 設計・実装計画を確定（L2/L3 は docs/designs + implementation-plans）
       │    2. Claude Code: create-codex-brief Skill で docs/codex-tasks/<feature>/ を生成
       │    3. 人間: Codex に指示書を渡して実行（下記コピペプロンプト）
       │    4. Claude Code: レビュー（06-ai-tools チェックリスト + 実画面確認）
       │    5. 差し戻しがあれば下記テンプレで再依頼 → 指摘全件の再レビュー
       │
       └─ Orchestrator ルート（設計判断が発生しうるタスク）→ CLAUDE.md 開発ワークフローへ
```

## 実行環境の選択肢

| 環境                                       | 状態           | 備考                                                                         |
| ------------------------------------------ | -------------- | ---------------------------------------------------------------------------- |
| 手元の Codex（CLI / IDE）                  | **今すぐ可能** | 指示書はリポジトリにコミット済みなので、pull して貼るだけ                    |
| Claude Code リモート環境から直接 Codex API | **ブロック中** | proxy で `api.openai.com` が 403・`OPENAI_API_KEY` 未設定（2026-06-24 観測） |

### リモート実行の解除条件（人間の操作が必要・課金に注意）

以下は**すべて人間がやる**こと。API 利用は従量課金が発生するため、Claude が代行・自動化しない。

1. Claude Code on the Web の環境設定でネットワークポリシーに `api.openai.com` を許可する。
2. 環境変数（Secrets）に `OPENAI_API_KEY` を設定する（リポジトリ・ログに書かない。
   `.claude/settings.json` の deny ルールにより Claude は秘密ファイルを読めない設計を維持）。
3. 解除後の運用: Claude が Bash 経由で Codex CLI を叩く形を試す。ただし**初回は必ず
   小タスク（L1 相当）で費用と品質を確認**してから常用を判断する。

解除しない場合も、手元実行ルートで運用は完結する（指示書生成までが Claude の担当範囲）。

## コピペプロンプト

### Codex 起動時（1 タスク = 1 セッション）

```text
AGENTS.md とそこに記載された docs/ を必ず読んでから着手してください。

以下の実装指示書に従って実装してください。指示書に書かれていない設計判断が
必要になった場合は、実装せずにその旨を報告して止まってください。

対象: docs/codex-tasks/<feature>/<NN-layer>.md

完了条件:
- pnpm lint / pnpm type-check / pnpm test が全 green
- 指示書の完了条件チェックリストが全て満たされている
```

### 差し戻し時

```text
レビューで以下の指摘がありました。全件を修正してください。
一部だけ直して残りを放置しないでください（修正後、全指摘に対する対応状況を
番号つきで報告してください）。

1. [指摘1: ファイルパス・行・内容・期待する修正]
2. [指摘2]
```

> 差し戻しの部分反映は既知のミス型（2026-06-06 実績）。**差し戻し後は指摘全件の
> 再レビューが必須**（06-ai-tools チェックリスト末尾）。

## レビュー手順（Claude Code 側）

1. `docs/06-ai-tools.md` の「Codex 実装のレビューチェックリスト」を全項目確認する
   （tsc/eslint を通過するミスが多いため、静的チェック green を根拠に省略しない）。
2. 指示書のシグネチャと実装の識別子を突き合わせる（タイポ検出）。
3. UI 変更を含む場合は `manual-browser-verify` Skill で実画面確認する。
4. 品質ゲート: `bash .claude/scripts/run-quality-gates.sh`。
5. レビュー結果をログ（AI ツール活用記録）に 1 行残す（ミス型の再発カウントが
   改善サイクルの入力になるため）。

## 安全境界

- 指示書の生成・レビューは Claude、**Codex の実行と API 鍵の管理は人間**。
- Codex 側から `main` へ push しない。作業ブランチ運用は CLAUDE.md の行動制約と同一。
- 指示書に秘密情報（接続文字列・鍵）を書かない。DB が必要なテストは PGlite
  （Infrastructure 層の既存パターン）を指定する。

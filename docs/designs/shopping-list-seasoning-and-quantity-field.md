# 設計: 調味料の買い物リスト除外 ＋ 数量・単位の統合入力欄

- 変更レベル: L2（複数層・複数ファイル。DB スキーマ変更なし）
- 対象: 献立→買い物リスト生成の材料集計 / 各入力フォーム（買い物リスト・在庫・レシピ・価格記録）
- 出典: ユーザー要望（2026-07-24 セッション）、`ingredient-aggregation.ts`、`.claude/rules/*`

## 背景・要望

1. 献立からレシピを選んで買い物リストを自動生成する際、**レシピに書かれた調味料は除外**したい
   （調味料は家に常備しているため毎回リストに出ると邪魔）。
2. 数量と単位が別々の入力欄になっていて**入力が手間**。1 つの入力欄にまとめたい。

## 要望1: 調味料の除外

### 判定方式（ユーザー確定: 名前で自動判定）

レシピ材料（`RecipeIngredient`）は UI 上 `productRef` が常に `null`（商品マスタ非連携）のため、
商品カテゴリ `調味料` では判定できない。よって**材料名（`displayName`）のキーワード判定**で行う。

- Domain 層に `isSeasoningName(name: string): boolean` を新設（`packages/domain/src/shared/seasoning.ts`）。
- 判定は `normalizeUnit` と同様に NFKC + trim 正規化してから照合する。
- 誤検出（別名・表記ゆれ）は許容する（ユーザー了承済み）。取りこぼした調味料は手動追加で対応可能。

#### 照合ルール（誤検出を抑える二段構え）

| 種別           | 例                                                                     | 照合             | 理由                                                     |
| -------------- | ---------------------------------------------------------------------- | ---------------- | -------------------------------------------------------- |
| 短く曖昧な語   | 塩 / 酒 / 酢 / 油 / だし                                               | **完全一致のみ** | 「塩鮭」「甘酒」「油揚げ」等の食材を誤除外しないため     |
| 識別性の高い語 | 醤油 / しょうゆ / 味噌 / みそ / みりん / 砂糖 / ごま油 / マヨネーズ 等 | **部分一致**     | 「薄口醤油」「赤味噌」「本みりん」も調味料として拾うため |

- 小麦粉・片栗粉・パン粉などの粉類は「乾物」寄りで買い足し対象になりうるため**除外対象に含めない**
  （必要ならリスト追記で拡張可能）。

### 適用箇所

`resolveMealPlanIngredients`（`ingredient-aggregation.ts`）の展開時に調味料材料をスキップする。
これにより `GenerateShoppingListUseCase`（初回生成）と `SyncShoppingListFromMealPlanUseCase`
（差分マージ）の両方で一貫して除外される。在庫引き算・店舗解決は除外後の材料に対して行う。

- 手動追加（`AddItemUseCase`）は除外対象外（ユーザーが明示追加したものは尊重する）。
- 対象外: レシピ表示、レシピ保存（調味料もレシピには残す。除外は買い物リスト生成時のみ）。

## 要望2: 数量・単位の統合入力欄

### 方針

数量（number）と単位（string）の 2 欄を、1 つのテキスト入力欄に統合する。

- パース規則: **先頭の数値（整数/小数/分数）＋残りを単位**。
  - 例: `3個`→`{value:3, unit:"個"}` / `300g`→`{300,"g"}` / `1.5本`→`{1.5,"本"}` / `1/2袋`→`{0.5,"袋"}`
  - NFKC 正規化で全角数字・全角単位を吸収（`３個`→`{3,"個"}`）。
- 共通ユーティリティ `parseQuantity(text)`（`apps/web/src/lib/parse-quantity.ts`）と
  共通コンポーネント `QuantityField`（`apps/web/src/components/ui/quantity-field.tsx`）を新設。
  `QuantityField` は「数量＋単位」を 1 欄で受ける自由入力（プレースホルダーで書式を案内）。
  datalist は単位単独の候補が結合値と一致せず補完が破壊的になるため付けない。

### 各フォームの適用

| フォーム                             | 現状                  | 変更後                                                 |
| ------------------------------------ | --------------------- | ------------------------------------------------------ |
| 買い物リスト手動追加 `add-item-form` | 数量 + 単位（2 欄）   | 分量（1 欄）。数値＋単位必須                           |
| 在庫追加 `add-stock-form`            | 数量 + 単位（2 欄）   | 分量（1 欄）。数値＞0＋単位必須                        |
| 価格記録 `price-record-form`         | 内容量 + 単位（2 欄） | 内容量（1 欄）。数値＞0＋単位必須                      |
| レシピ材料 `ingredient-row`          | 量 + 単位（2 欄）     | 分量（1 欄）。数値＋単位→amount、数値なし→amountNote   |
| 商品マスタ `product-form-fields`     | 基本単位（単位のみ）  | **対象外**（数量を伴わない単位単独入力のため現状維持） |

- レシピ材料は「数値なし入力（例: 少々）」を従来どおり `amountNote` として扱えるよう、
  `parseQuantity` が「数値で始まらない」場合は note 扱いを返す。`build-ingredient-input` は
  この結果で amount / amountNote を振り分ける。
- 数値のみで単位が無い入力（例: `3`）は、単位必須のフォーム（買い物・在庫・価格）では不正として
  送信を無効化。レシピでは note 扱い。

### パース仕様 `parseQuantity(text): ParsedQuantity`

```
type ParsedQuantity =
  | { kind: 'amount'; value: number; unit: string }  // 先頭が数値かつ単位あり
  | { kind: 'note'; note: string }                   // 数値で始まらない（自由記述）
  | { kind: 'valueOnly'; value: number }             // 数値のみ（単位なし）
  | { kind: 'empty' };                                // 空
```

- 呼び出し側の必須要件に応じて `kind` を解釈する（買い物/在庫/価格は `amount` のみ受理、
  レシピは `amount`→amount・`note`/`valueOnly` 以外の非数値→amountNote）。

## 非対象

- DB スキーマ変更（レシピ材料への調味料フラグ追加等）は行わない（名前判定方式のため不要）。
- 商品マスタの基本単位入力の統合（数量を伴わないため）。
- 調味料キーワードの管理 UI（当面はコード内の固定リスト）。

## テスト観点

- Domain: `isSeasoningName` — 完全一致語 / 部分一致語 / 誤検出防止（塩鮭・油揚げ・甘酒）/ 正規化。
- Application: generate / sync で調味料材料が除外されること、非調味料は従来どおり集計されること。
- Web: `parseQuantity` の各分岐、`QuantityField` の入出力、各フォームの送信値・バリデーション、
  レシピの note 振り分け。
